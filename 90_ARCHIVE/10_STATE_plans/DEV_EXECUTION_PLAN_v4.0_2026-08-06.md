## 1. 착수 전 기준선과 안전 절차

1. `.project-continuity`의 유효한 타인 락과 최근 수정 파일을 확인한다.
2. 이 작업 원본은 Git 저장소가 아니므로 `git init`, pull, commit, push, branch를 하지 않는다.
3. 수정할 파일을 `LOCK.<작업자>.json`에 먼저 적고 충돌을 재확인한다.
4. 연속성 기록을 포함한 수정 대상의 하드링크를 확인하고, 링크 파일은 제자리 쓰기 전에 안전하게 분리한다.
5. 최신 후보를 수정하지 않은 상태로 전체 회귀한다. 현재 기준선 실패는 새 기능 실패와 분리한다.
6. 각 묶음의 로직:문자열 증가량을 1:1로 견적하고, 완주 후 압축된 실제 크기를 기록한다.

기준선 검사 러너는 프로젝트에 있는 `.test-venv\Scripts\python.exe`와 `40_TESTS`, `70_TOOLS\run_all_tests.py`를 우선 재사용한다. 새 프로그램·라이브러리는 설치하지 않는다.

## 2. 공통 구현 계약

### 2.1 상태 정직성

- 엔진 상태는 `setup_needed`, `disconnected`, `checking`, `limited`, `protected` 다섯 개를 유지한다.
- `protected`는 터널·경로·DNS 등 필수 근거가 모두 참일 때만 가능하다.
- UI의 `확인 불가(unverified)`는 엔진의 여섯 번째 상태가 아니라 근거 부족을 설명하는 표시 규칙이다.
- 실제 운영 자료가 없는 서버·사용량·성공률·복구 예상은 확정 수치로 표시하지 않는다.

### 2.2 개인정보와 기기 통제

- 비밀키, 원본 VPN 설정, 실제 IP, 계정, 토큰, 원문 로그를 화면·기록·진단 복사에 남기지 않는다.
- 발급·재발급·해지·모든 기기 초기화는 영향 범위와 되돌릴 수 없음을 먼저 보여 준다.
- 기록·알림·분석은 기기 안 저장 또는 명시 동의가 기본이다. 거절해도 핵심 연결 기능은 유지한다.

### 2.3 도달성·반응형·접근성

- 각 기능은 홈·메뉴·오류·단축키 중 한 곳 이상의 실제 진입 경로가 있어야 한다.
- 1024px 미만 모바일 회귀를 보호하고 1280·1920 PC 레이아웃을 검사한다.
- 키보드 포커스, 의미 있는 이름, 색 이외 표식, 큰 글씨·고대비·움직임 줄이기를 공통 계약으로 적용한다.

## 6. 출시 열차 운영

작업 묶음 하나가 배포 가능한 최소 출시 단위다. 다음 다섯 요건을 모두 만족해야 다음 묶음으로 넘어간다.

1. 가시 변화와 실제 도달 경로
2. 정상·음성 전용 검사
3. 전체 회귀와 용량 실측
4. 개인정보·실제/미확인 상태 검토
5. 별도 배포 승인 후 공개 주소 확인·되돌리기 확인

배포 승인이 없으면 로컬 검증 완료와 배포 대기를 구분한다. 신규기능 개발은 안전한 로컬 범위에서 다음 묶음으로 이어갈 수 있지만 공개 완료로 기록하지 않는다.

새 작업이 들어오면 다음 순서로 판정한다.

1. 보안·개인정보·전면 장애인가 → 즉시 안전 조치 후 현재 신규기능으로 복귀
2. 현재 작업 묶음을 막는 기반인가 → 같은 묶음의 선행 작업으로 편입
3. 100개 중 하나인가 → 해당 F0~F6 순서에 편입
4. 기존 유지보수인가 → 현재 묶음 회귀에 필요한 부분만 처리
5. 마케팅·장식·수익화·새 아이디어인가 → `PARKED_AFTER_F6`

우선순위 변경은 조용히 하지 않는다. 이유·승인·영향받는 ID·복귀 지점을 기록한다.

## 8. 용량·성능·절단 규칙

- 작업 묶음마다 착수 전 견적과 완료 후 압축 실측을 기록한다.
- 500줄 이상 또는 예산 초과가 예상되면 UI, 기기 안 데이터, 실제 연동으로 나눠 출시한다.
- 상태 정직성·개인정보 가림·삭제권·기본 접근성은 절단하지 않는다.
- 장식 애니메이션, 부가 차트, 추천 설명 확장은 먼저 자른다.

## 9. 중단·롤백 조건

- 실제 보호 오표시
- 비밀값·실제 IP·원본 설정 노출
- 모바일 기존 흐름 회귀
- 다른 기기 설정의 오해지
- 실제 자료 없는 실시간/정상 표시
- 키보드·보조기술로 핵심 행동 불가

발생하면 현재 묶음의 노출을 되돌리고 마지막 통과 단위로 복구한다. 실패 원인과 손상 범위를 기록하고 다음 묶음으로 넘어가지 않는다.
