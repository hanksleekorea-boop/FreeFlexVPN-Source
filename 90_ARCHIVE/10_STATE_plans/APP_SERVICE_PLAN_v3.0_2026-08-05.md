## 0. 이번 버전의 결정

v3는 화면을 더 많이 만드는 계획이 아니라, **사용자가 지금 보호되었는지·문제가 나면 무엇을 해야 하는지·여러 기기를 어떻게 통제하는지**를 정직하게 알 수 있게 하는 계획이다. v2의 무로그인, 기기 안 데이터 우선, 자동 청구 없음, 사용량과 신뢰를 숨기지 않는 원칙을 유지한다.

현재 공개 화면에는 QR 기반 Android 설정 안내, 반응형 PC 화면, 기본 대시보드가 있다. 그러나 A56 실제 점검에서는 일반 인터넷 연결은 확인되었어도 현재 WireGuard 활성 세션·터널 경로는 확인하지 못했다. 따라서 현시점 제품은 “VPN 보호 확인이 완료된 서비스”가 아니다. 모든 화면과 문구는 이 한계를 반영한다.

## 1. 누구를 위한 서비스인가

1. 공용 Wi‑Fi를 쓰는 여행자와 원격 근무자: 빠른 연결보다 **보호 사실 확인**을 원한다.
2. Android와 iPhone, PC를 함께 쓰는 사람: QR 한 번으로 끝나는 설정과 기기별 통제를 원한다.
3. VPN에 익숙하지 않은 사람: 오류 코드가 아니라 다음 한 행동을 원한다.
4. 키보드·큰 글씨·화면 읽기 기능이 필요한 사람: 같은 핵심 기능에 동등하게 도달해야 한다.

제외 범위는 불법 행위 회피, 보안·익명성의 절대 보장, 실제 자료 없는 속도·혼잡·법률의 확정 표시이다.

## 2. 핵심 약속과 화면 문장

| 약속 | 화면에서 지킬 표현 | 금지 표현 |
|---|---|---|
| 보호 사실 | `연결됨`, `확인 중`, `확인 불가`를 분리 | `완전 보호됨` 단정 |
| 데이터 | `기기 안에 저장`, 외부 전송 시 목적·동의 표시 | 모호한 “안전하게 처리” |
| 문제 해결 | 원인·다음 행동·진단 복사 | 오류 번호만 표시 |
| 여러 기기 | 기기별 발급·해지·상태 | 한 기기의 성공을 모든 기기의 성공으로 표시 |
| 운영 정보 | 실제 출처·갱신 시각 | 실시간처럼 보이는 예시 수치 |

## 3. 서비스 구조

### 3.1 모바일 — 빠르게 확인하고 복구하는 손

홈은 보호 상태, 가장 가까운 다음 행동, 최근 결과, 기기 설정 관리로 구성한다. QR 가져오기 실패와 네트워크 전환은 정상 흐름의 일부로 취급한다. P0-01~P0-10, P1-19~P1-25, P2-31~P2-32, P3-41~P3-45, P4-51~P4-80을 주로 제공한다.

### 3.2 PC — 넓게 점검하고 관리하는 책상

1024px 이상에서는 기기 목록·보호 상태·사용량/기간 비교·QR 핸드오프를 한 화면에 나란히 보인다. 키보드만으로 핵심 행동을 할 수 있어야 한다. 기존 1024px 미만의 폰 레이아웃은 바꾸지 않는다. P2-33~P2-39와 P4-81~P4-92가 핵심이다.

### 3.3 신뢰·지원 — 문제가 생겨도 버려지지 않는 길

상태 페이지, 정비·장애·개인정보·보안 이력, 가린 진단 정보, 요청 상태를 한 흐름으로 연결한다. P1-11~P1-18, P3-46~P3-50, P4-58~P4-66, P4-93~P4-100이 핵심이다.

## 5. 제품 원칙과 결정 경계

1. **사실 우선:** 실기기·서버 확인 전에는 예시나 추정을 실제처럼 말하지 않는다.
2. **기기 통제:** 설정 발급, 재발급, 해지, 긴급 초기화는 사용자에게 영향과 되돌릴 수 없음을 먼저 알린다.
3. **낮은 위험 기본값:** 진단·분석·알림은 선택형이며, 거절해도 VPN 핵심 흐름을 막지 않는다.
4. **찾을 수 있어야 존재:** PC 기능은 홈·메뉴·QR 또는 단축키 도움말에서 실제 도달 가능해야 한다.
5. **같은 앱:** PC는 별도 사이트가 아닌 같은 반응형 서비스다. 별도 PC 앱은 용량·검사 비용 실측이 예산을 깨는 경우에만 재검토한다.
6. **비용·배포 경계:** 결제, 서버 비용, push, 배포, 실제 기기 설정 변경은 그때그때 사용자의 명시 승인을 받는다.

## 6. 제품 지표와 증거의 등급

| 등급 | 뜻 | 현재 예 |
|---|---|---|
| A: 실제 확인 | 실제 기기·실제 서버에서 재현 | A56 일반 인터넷·DNS 확인 |
| B: 자동 검사 | 코드가 정한 조건을 자동으로 검사 | UI·QR·반응형 검사 |
| C: 가상 분석 | 다양한 가상 인물의 행동 가설 | 1,000명 사용성 분석 |
| D: 사용자 조사 | 동의한 실제 사용자 응답 | 아직 없음 |

우선순위는 C와 기존 검사에서 출발했다. 출시 판단은 P0에서 A와 B 증거가 모두 있어야 하며, 고객 만족·채택 주장은 D가 생기기 전까지 하지 않는다.

## 8. 범위 절단 규칙

- P0의 실제 확인 통로가 없으면 차트·추천·마케팅 문구를 먼저 늘리지 않는다.
- 실제 운영 자료가 없으면 상태 화면은 `준비 중` 또는 마지막 검증 시각만 보인다.
- 500줄 이상 변경 또는 용량 예산 초과 예상 시, 한 릴리스를 더 작은 독립 기능으로 자르고 재측정한다.
- 모바일 회귀가 한 건이라도 실패하면 PC·추가 기능 배포를 멈춘다.
- iPhone 실기기 검증 전에는 iPhone 흐름을 `안내 제공`, `실기기 확인 전`으로 표시한다.

## 9. 현재 기준선과 다음 행동

2026-08-05 기준 자동 UI 관련 128건은 통과했으나, 이것은 VPN 터널 보호를 뜻하지 않는다. A56의 현재 점검에서는 일반 연결은 확인되었고 활성 WireGuard 세션·터널 경로는 확인되지 않았다. 다음 개발 첫 행동은 **T0의 보호 상태 데이터 모델과 미확인 화면을 설계하고, 실제 확인 가능한 검사 경로를 먼저 만드는 것**이다.
