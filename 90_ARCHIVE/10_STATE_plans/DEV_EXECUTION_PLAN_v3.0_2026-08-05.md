## 0. 실행 결론

100개 항목은 모두 만들되, 한 번에 화면만 늘리지 않는다. 첫 개발은 `T0 사실 기반`이다. 연결 UI가 있어도 실제 터널·경로·DNS가 확인되지 않으면 보호됨이라고 표시하지 않는 데이터 모델과 화면을 먼저 만든다. 이어서 설정·복구, 운영 자료, 여행·기기, PC, 접근성·신뢰 순으로 간다.

현재 근거: A56에서 일반 인터넷·DNS는 확인되었으나 활성 WireGuard 세션과 터널 경로는 확인하지 못했다. iPhone 실기기 증거는 없다. 따라서 T0 이전의 라이브 기능은 모형 또는 안내일 뿐이며, 실제 보호 기능이라고 출시하지 않는다.

## 1. 공통 기술·검사 계약

| 계약 | 구현 규칙 | 검사 |
|---|---|---|
| 상태 정직성 | `confirmed`, `checking`, `unverified`, `failed`, `demo`를 분리 | 상태 전이 단위 검사 + 미확인 음성 검사 |
| 개인정보 | 키·원본 설정·실제 IP·계정·원문 로그를 저장/복사하지 않음 | 금칙어·가림 처리 검사 |
| 도달성 | 기능마다 홈/메뉴/오류/단축키 중 실제 진입 경로 1개 이상 | 링크·포커스·키보드 검사 |
| 반응형 | 1024px 미만 기존 모바일 회귀 보호, 1280·1920 PC 검사 | 뷰포트 비교 검사 |
| 접근성 | 의미 있는 이름, 포커스, 색 이외 표식, 큰 글씨 | 키보드·접근성 검사 |
| 배포 경계 | push·배포·비용·실기기 설정 변경은 대화의 명시 승인 필요 | 승인 기록 확인 |

### 공통 데이터 모델 초안

`ProtectionCheck`은 `status`, `checkedAt`, `checks`(터널/경로/DNS), `source`, `safeSummary`만 가진다. `DeviceConfig`는 표시명·발급/해지 상태·마지막 확인 시각만 가진다. 원본 키와 설정 전문은 브라우저 화면·진단 복사·분석 기록에 넣지 않는다. `OperationalStatus`는 실제 출처가 연결된 경우에만 `source`, `updatedAt`, `confidence`를 가진다.

## 3. 열차별 세부 작업

### T0 — 사실 기반 보호 상태

1. 상태 열거값과 상태 전이표를 코드/문서에 한 곳으로 고정한다.
2. 상태 카드에 `확인됨`, `확인 중`, `확인 불가`, `문제 발생`을 아이콘·텍스트·시간으로 함께 표시한다.
3. 종료 IP, DNS, 경로는 실제 검사값이 있을 때만 표시하고, 없으면 “이 기기에서 아직 확인하지 못함”을 표시한다.
4. 보호 범위 설명에서 VPN이 막지 못하는 위험과 사용자의 다음 행동을 보여 준다.
5. 의도적으로 검사 어댑터가 비어 있는 경우, “보호됨”이 아니라 `확인 불가`가 나오는 음성 검사를 추가한다.

완료 조건: UI 정상/실패/미확인 상태, 모바일 회귀, PC 기본 카드, 문구 금칙어 검사를 통과한다.

### T1 — 설정과 복구

1. 기기 목록, 표시명 변경, 재발급, 해지, QR 만료와 가져오기 확인을 분리한다.
2. QR 스캔 실패, 형식 오류, 카메라 권한 거부, 만료 설정에 각각 한 화면 한 행동을 제공한다.
3. 연결 이력은 기기 안에 최소 범위로 저장하고 사용자가 삭제할 수 있게 한다.
4. 문의용 진단은 앱 버전·안전한 상태 요약만 복사하며 키·IP·원본 설정을 제거한다.

완료 조건: 한 기기의 해지가 다른 기기 설정을 바꾸지 않고, 잘못된 QR/끊김/DNS 실패에서 복구 카드가 보이며, 민감정보 검사 0건이다.

### T2 — 운영 자료와 개인 요약

1. 서버 상태·혼잡·정비·장애·사용량은 `데이터 출처`, `마지막 갱신`, `알 수 없음` 상태를 공통으로 쓴다.
2. 실제 운영 API 전에는 모형 수치 대신 빈 상태/준비 중 상태를 쓴다.
3. 성공률·예상 소진·월간 요약은 기간·표본·추정 여부를 표시한다.
4. 알림은 기본 꺼짐, 시간대·종류·끄기를 제공한다.

완료 조건: 오래된 자료는 현재 상태처럼 보이지 않고, 기기 안 이력 삭제·내보내기가 동작하며, 장애 상태가 홈/도움말에서 도달 가능하다.

### T3 — 이동 중 사용과 여러 기기

1. 항상 켜기·차단 모드·공용망·네트워크 전환 안내를 OS별로 분리한다.
2. 여행·지역 이용 가능성·법률은 확인일과 한계를 같이 표시하고 법률 자문처럼 말하지 않는다.
3. 서버 추천은 이유와 직접 선택·추천 끄기를 제공한다.
4. 긴급 해지는 되돌릴 수 없음과 영향 기기 목록을 확인한 뒤 실행한다.
5. iPhone은 실기기 확인 전까지 `안내 제공/실기기 확인 전` 상태로 관리한다.

완료 조건: Android/iOS/PC 각 안내가 실제 메뉴에서 찾아지고, 긴급 해지·재발급·복구의 권한/확인 흐름을 음성 검사한다.

### T4 — PC 작업대

1. 같은 단일 HTML의 반응형 확장으로 1280px와 1920px에서 기기·요약·통계·QR을 다단으로 보인다.
2. 1024px 아래의 기존 화면은 픽셀 또는 구조 회귀 검사에서 변경 0을 목표로 한다.
3. 스페이스/엔터와 방향키는 브라우저 기본 동작과 충돌하지 않게 범위를 제한하고, `?`에서 도움말을 연다.
4. QR은 정본 주소로 해독되며 만료/재발급 상태를 표시한다.

완료 조건: `pc_viewport_test`, `keyboard_test`, `pc_home_test`, `pc_handoff_test`와 기존 모바일 전체 회귀를 한 번에 통과한다.

### T5 — 모두를 위한 신뢰

1. 다국어·큰 글씨·고대비·화면 읽기·움직임 줄이기·저속망·저시력 간단 모드를 핵심 흐름에서 검사한다.
2. 신뢰 센터에는 기기 저장, 삭제, 보안 이력, 약관 변경, 지역 안내 확인일을 보여 준다.
3. 의견·버그·기능 요청은 선택형이고, 접수 후 상태를 보인다. 거절해도 기능은 줄지 않는다.
4. 정기 접근성·신뢰 점검 결과는 미해결 위험을 포함해 공개한다.

완료 조건: 키보드만으로 모든 핵심 버튼에 도달하고, 색만으로 상태를 말하지 않으며, 동의 거절 후에도 서비스의 핵심 행동이 가능하다.

## 4. 검사 매트릭스

| 구분 | 자동 검사 | 음성 검사 | 실제 확인 |
|---|---|---|---|
| 보호 상태 | 상태 전이·금칙어·UI 렌더 | 검사값 없음·오래된 값·실패 | 터널/경로/DNS가 가능한 실기기에서 확인 |
| 설정/QR | 형식·만료·해지·가림 처리 | 잘못된 QR·권한 거부·만료 | Android, 이후 iPhone 각각 가져오기 |
| 운영 자료 | 출처/시간/빈 상태 | API 없음·오류·오래된 데이터 | 실제 운영 시스템 연결 후 표본 대조 |
| PC | 1280/1920 다단·키보드 | 1023px 회귀·포커스 누락 | PC 브라우저 수동 점검 |
| 접근성 | 이름·포커스·대비 규칙 | 색만 구분·움직임 강제 | 보조기술/기기별 수동 점검 |

`실제 확인` 칸은 자동 통과로 대체하지 않는다. 실제 기기 검증 결과가 없으면 문서와 화면에서 그 사실을 유지한다.

## 5. 변경량·용량·절단 계획

각 열차 착수 전에 로직 바이트와 사용자 문구 바이트를 1:1로 견적 내고, 완료 후 압축된 실제 값을 기록한다. 500줄 이상 바뀌거나 예산 초과가 예상되면 다음 순서로 자른다: (1) 표시만 하는 화면, (2) 기기 안 데이터, (3) 실제 운영 연동. P0 상태 정직성과 개인정보 가림은 자르지 않는다.

## 6. 배포 판정과 롤백

- 각 열차는 가시 변화, 전용 검사, 전체 회귀, 공개 후 확인 경로, QR/도달성 검사를 만족해야 완료다.
- 배포 채널이 막히면 실측·조건 매트릭스·사용자가 해야 할 최소 행동을 상태 기록의 최상단에 남긴다.
- 배포 후 보호 상태 오표시, 비밀값 노출, 모바일 회귀, 해지 오작동이 나오면 즉시 해당 기능 노출을 되돌리고 원인을 기록한다.
- 이 문서는 배포·push·비용·실기기 설정 변경을 승인하지 않는다.

## 7. 첫 실행 체크리스트

1. 최신 후보를 수정 없이 전체 회귀한다.
2. T0의 상태 모델과 미확인 카드만 작은 변경으로 구현한다.
3. 상태 정상/미확인/실패 음성 대조와 기존 UI 회귀를 한 번에 실행한다.
4. 용량 실측, 증거, 다음 하나의 행동을 `.project-continuity`에 남긴다.
5. 사용자 승인 없이는 push·배포·과금·실기기 설정 변경을 하지 않는다.

## 8. 인계 기준

다음 작업자가 가장 먼저 할 일: **T0 보호 상태의 실제 검사 입력이 현재 코드에 존재하는지 확인하고, 없으면 `unverified` 카드와 음성 검사부터 구현한다.**
