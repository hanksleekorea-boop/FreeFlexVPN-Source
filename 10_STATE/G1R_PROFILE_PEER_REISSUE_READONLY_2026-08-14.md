# G1-R 기존 Android 프로필·서버 피어·재발급 읽기 전용 비교

판정 시각: 2026-08-14 · 상태: **READBACK REQUIRED** · 실제 기기/서버 변경: **0건**

## 판정 경계

- 기존 `ffvpn`과 별도 검증 프로필은 삭제·덮어쓰기·자동 활성화하지 않는다.
- 개인키·공개키·설정 원문·endpoint·할당 주소·실제 IP·계정 식별값은 입력·출력·증거에 넣지 않는다.
- 과거 별도 검증 프로필의 터널·DNS·서버 악수·일반망 복귀 성공은 보존하지만, 오늘의 후보나 기존 `ffvpn`이 정상이라는 증거로 승격하지 않는다.
- 판정기는 후보 발급·서버 피어 변경·기기 설정 변경을 실행하지 않으며, 검토 가능한 다음 단계만 반환한다.

## 현재 비교 결과

| 구분 | 현재 근거 | 판정 |
|---|---|---|
| Android | 마지막 기록에서 기존·후보 프로필이 모두 존재하고 꺼짐, 항상 연결·차단 모드 꺼짐 | `historical_record`; 현재 ADB 실행 도구가 없어 live readback 아님 |
| 기존 프로필 | 켰을 때 DNS·경로 실패 이력 | 실패 이력 보존, 설정은 보존 |
| 별도 검증 프로필 | 과거 터널·DNS·서버 악수·끔 뒤 일반망 복귀 성공, 외부 경로 일치·사람 직접 전환은 미확인 | 현재 후보 통과로 승격 금지 |
| 서버 | 이 실행 환경에서 실시간 피어·전달·NAT·방화벽 readback 없음 | 피어 대응·재발급 필요성 확정 금지 |
| 자동 판정 | `readback_required` | `legacy_profile_action=preserve`, 모든 mutation 0 |

최신 기계 판정은 `10_STATE/G1R_PROFILE_REISSUE_READONLY_2026-08-14.json`이다. 로컬 `60_OUTPUTS/checks/`의 선행 실행 파일은 현재 판정 이유를 보강하기 전후의 임시 증거이며 인계 정본에 포함하지 않는다.

## 다음 readback에 필요한 값

서버에서는 피어 개수, 기존/후보 대응의 `present|absent|unknown`, 전달·NAT·방화벽의 `true|false|null`만 받는다. Android에서는 기존/후보 존재·켜짐, 항상 연결, 차단 모드와 근거가 현재 live readback인지 여부만 받는다. 키·주소·설정 원문 없이도 다음 경로를 구분할 수 있다.

1. 양쪽 readback 미완료 → 기존 프로필 보존, 비교 계속.
2. 서버와 기기에서 후보가 모두 없음 + 기반 상태 정상 → 별도 후보 발급 **승인 요청 가능**. 자동 발급은 하지 않음.
3. 후보의 기기/서버 대응 불일치 → 새 발급보다 매핑 원인 조사.
4. 현재 후보에서 사람 직접 전환과 터널·외부 경로·DNS·악수·일반망 복귀가 모두 통과 → 기존 피어 폐기 **검토 요청 가능**. 자동 폐기는 하지 않음.
5. 하나라도 실패 → 후보와 기존 설정을 보존하고 실패 원인만 조사.

## 실행 명령

```powershell
& $python -X utf8 70_TOOLS\compare_profile_reissue.py `
  --input <민감정보 없는 새 readback.json> `
  --output <새 증거 파일.json>
```

출력 파일은 기존 파일을 덮어쓰지 않는다. 다음 첫 행동은 ADB가 사용 가능한 상태와 서버 읽기 권한을 확보한 뒤, 설정을 바꾸지 않고 live device/server readback을 한 번씩 수집하는 것이다.
