# FreeFlexVPN v2.6 R6 후보 결속 사전검사 계획

> 상태: `VERIFIED_IMPLEMENTED_LOCAL`  
> 날짜: 2026-08-02  
> 이전 후보·롤백: v2.5 설정 전용 사전검사

## 쉬운 요약

실제 서버를 검사할 때 현재 후보에 속하지 않은 서버가 공개 목록에 끼어 있으면 이제 무조건 멈춘다.
같은 서버가 두 번 나오거나 서버 ID가 비어 있는 행도 통과시키지 않는다.

## 실측한 빈틈

이전 판정은 공개 카탈로그를 현재 후보 서버 ID로 먼저 걸러낸 뒤 health와 비교했다.
그래서 후보 밖 서버 행은 비교 전에 사라져, 정상 후보 2대와 함께 섞여 있어도 사전점검이 통과할 수 있었다.

## 결과 계약

- 공개 카탈로그의 모든 행은 현재 R6 후보의 서버 ID에 정확히 속해야 한다.
- 알 수 없는 서버, 중복 서버, 비어 있거나 잘못된 행이 하나라도 있으면 `ready=false`다.
- 상세 증거에는 민감한 host·IP·endpoint·키를 넣지 않고 잘못된 행의 개수만 기록한다.
- 설정 전용 `--config-only`의 네트워크 요청 0건·`ready=false` 경계는 그대로 유지한다.

## 검증

- R6 사전점검 9/9 통과: 정상 2공급자 후보 PASS, 후보 밖·중복·빈 행 음성 대조 FAIL.
- 연결 회귀 37/37 통과: 제어 런타임 8, 서버 카탈로그 10, SSH 어댑터 10, R6 9.
- 검사기 사전진단 2/2 통과: 필수 모듈 정상/누락 경로.
- 전체 회귀는 현재 번들 Python에 Playwright·OpenCV가 없어 시작 전 정직하게 중단한다. 기존 코드 실패로 판정하지 않는다.

## 증거 경계

- I/L: 구현과 로컬 표적·연결 회귀 증거 있음.
- B/P: 이번 변경은 서버 제어면 코드이며 새 공개 앱 릴리스 없음.
- D/U: 실제 서버·대상 기기·독립 사용자 증거 없음.
- v2 기준선: 7/12 = 58.3% 유지.

## 다음 관문

같은 candidate ID와 외부 설정으로 `--config-only`를 먼저 통과한 뒤 실서버 모드를 실행한다.
서로 다른 공급자 2곳의 최신 health·카운터·정확히 결속된 카탈로그가 모두 통과해야 V2-M8 증거가 된다.

## 롤백

`r6_preflight.py`의 `catalog_rows_are_candidate_bound` 검사와 해당 음성 대조를 제외하면 v2.5 판정으로 돌아간다.
v2.5 계획·증거와 공개 v2.3 앱은 수정하지 않는다.
