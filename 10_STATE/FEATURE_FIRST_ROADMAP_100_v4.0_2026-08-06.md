## 1. 최우선 편성 선언

이 문서의 F0-1부터 F6-2까지 20개 작업 묶음은 기존 대기 기능, 마케팅 실험, 장식 개선, 신규 수익화보다 먼저 개발한다. 순서를 앞설 수 있는 예외는 다음 네 가지뿐이다.

1. 실제 보안 사고 또는 비밀값 노출 차단
2. 개인정보 손상 또는 데이터 유실 차단
3. 공개 서비스 전면 장애 복구
4. 신규기능 열차를 막는 필수 기반 수정

예외를 사용하면 이유·영향·복귀할 작업 묶음을 `HISTORY.md`에 기록한다. 그 밖의 기존 작업은 `PARKED_AFTER_F6` 상태로 둔다.

## 2. 증거 등급

- A: 실제 기기·실제 서버에서 확인
- B: 자동 검사에서 확인
- C: 가상 사용자 분석에서 도출한 가설
- D: 동의한 실제 고객 조사

100개 우선순위는 주로 B·C 증거에서 출발했다. A56의 일반 인터넷·DNS는 확인했지만 활성 WireGuard 세션·터널 경로는 확인하지 못했고, iPhone 실기기 증거는 없다. 따라서 실제 보호·iPhone 완료 표시는 A 증거가 생기기 전까지 금지한다.

## 4. 묶음별 출시 5요건

각 작업 묶음은 다음 다섯 가지가 모두 있어야 `완료`다.

1. 사용자가 찾을 수 있는 가시 변화
2. 해당 묶음 전용 정상·음성 검사
3. 기존 모바일·PC·QR·보호상태 전체 회귀
4. 데이터 출처·개인정보·미검증 상태 확인
5. 배포 승인 후 공개 주소 확인과 되돌리기 증거

배포 승인이 없으면 1~4를 마친 상태를 `배포 대기`라고 기록하며 `완료`라고 부르지 않는다.

## 5. 기존 기능과의 관계

- 현재 기능을 유지하는 회귀 수정은 해당 신규기능 묶음 안에서 함께 처리한다.
- 화면 장식만 바꾸는 일, 근거 없는 실시간 수치, 신규 마케팅·추천 보상·수익화 실험은 F6-2 이후다.
- 보호 상태 정직성, 비밀값 차단, 사용자가 데이터를 삭제할 권리는 일정 때문에 자르지 않는다.
- 별도 PC 사이트를 만들지 않고 같은 반응형 앱을 확장하는 기본안 A를 유지한다.

## 6. 다음 첫 행동

F0-1을 시작한다. 수정 전 전체 기준선 회귀를 실행한 뒤, `evaluate_connection()`의 다섯 상태 계약을 유지하면서 UI가 실제 검사 입력 없이 `protected`를 표시하는 우회 경로가 있는지 확인한다. `unverified`는 엔진의 여섯 번째 상태가 아니라 UI의 정직한 표현으로 구현한다.
