# 범용 실기기·공개 서비스 종합 QA 실행 프롬프트 v1.1

## 변경 이력

- 새 버전: v1.1
- 이전 버전: v1.0
- 이번 실행에서 발생한 문제: 기본 검사 환경의 네트워크 차단, 다른 작업자 사용 여부가 미확인인 기기, 정체 미확인 무선 신호, PC QR 화면 자동 제어 제한.
- 채택한 해결책: 공개 응답은 일반 네트워크의 읽기 전용 요청으로 교차 확인하고, 기기 사용 여부가 미확인이면 조작하지 않으며, 모델 확인 전 무선 주소에 연결하지 않는다. QR 화면이 막히면 기기 모델이 확인된 페어링 코드 경로만 대안으로 쓴다.
- 아직 해결되지 않은 문제: 실제 기기 핵심 흐름과 기기 설정 변경 검사는 승인 기기·사용 가능 상태가 필요하다.
- 다음 실행에서 달라지는 점: 기기 발견 결과를 먼저 표로 보고하고, 기기별 사용 가능 선언 또는 잠금 확인이 없으면 공개·자동·가상 검사만 계속한다.

## 3. 시작과 안전 규칙

1. 반드시 `adb devices -l`부터 실행하고, 가린 식별자·모델·연결 방식·ADB 상태·승인·다른 작업자 상태를 표로 먼저 보고한다.
2. 모델·연결 방식·승인·다른 작업자 미사용·`device` 상태가 모두 맞는 기기만 조작한다.
3. 다른 작업자 상태가 미확인이면 **사용하지 않는다**. 전경 앱이나 다른 프로젝트의 ADB 프로세스만으로 사용 가능이라고 추측하지 않는다.
4. 모델이 확인되지 않은 무선 주소·mDNS 신호에는 연결하지 않는다. 사용자가 정확한 기기 정체를 확인한 주소만 일시적으로 쓴다.
5. 기존 화면·탭·방문 기록·다른 앱 데이터는 읽지 않는다. 승인 기기에서는 먼저 대상 URL 또는 지정 앱으로 이동하고, 대상 화면이 열린 뒤에만 구조·캡처를 확인한다.
6. 허용: 대상 URL 열기, 대상 서비스 안의 테스트 입력, 대상 화면 캡처, 안전한 ADB 재연결, 공개 URL 읽기 전용 응답 검사.
7. 금지: 인증 우회, 정체 불명 기기·다른 작업자 기기 조작, 실제 사용자 데이터 열람, 초기화·삭제·계정 변경, 앱 설치·제거, 기기 설정 변경, 비용·배포·외부 메시지, 범위 밖 데이터 추출.
8. 화면 읽기·네트워크 끄기·VPN 변경 등 기기 설정 변경은 이 프롬프트 입력값에 별도 승인 문장이 있을 때만 실행한다. 없으면 구조 검사까지만 하고 UNVERIFIED로 남긴다.

## 4. 공개 상태 선검사

1. 공개 URL마다 실제 GET의 상태·최종 주소·프로젝트 표지를 확인한다. 제한된 실행 환경에서 실패하면 일반 네트워크의 읽기 전용 요청으로 한 번 교차 확인하고, 둘 다 실패할 때만 서비스 오류 후보로 기록한다.
2. 대시보드는 URL·프로젝트명·버전·갱신 시각·진척 수치를 확인한다. URL이 없으면 공개 상태는 UNVERIFIED다.
3. QR은 실제 해독값을 정규화해 최신 공개 URL과 비교한다. 이미지 표시만으로 통과시키지 않는다.

## 5. 실제 기기 검사

승인된 기기에서 다음을 실제 터치·구조·대상 화면 캡처·예상 대비 결과로 남긴다: 첫 화면, 탐색, 핵심 선택, 핵심 행동, 목록·상세·저장, 개인정보·권한, 프로젝트별 네트워크·VPN·지역 안내, QR, 오프라인, 온라인 복귀, 뒤로가기·새로고침·재실행, 작은 화면·큰 글자·키보드, 오류·복구.

해당하지 않는 항목은 시작 전에 이유·재배분 가중치를 기록한다. 실행하지 않은 항목을 PASS나 완료로 쓰지 않는다.

## 6. 실패 복구

실패 시 최소 오류와 기기 별칭만 기록하고, 같은 조건 1회 재시도 → 연결·브라우저·응답 분리 → 같은 승인 기기 ADB 재연결 → 다른 안전한 방법 교차 확인 → 작은 단계로 분해 순서로 진행한다. 같은 방법 3회 실패 시 다른 방법으로 전환한다. QR UI가 열리지 않으면 정체가 확인된 기기에 한해 페어링 코드 방식을 대안으로 사용한다.

## 7. 가상 사용자 상황 분석

{{DOMAIN_SCOPE}} 안에서 서로 다른 최대 1,000개 상황을 만든다. 연령·숙련도·기기·접근성·국가·언어·불안정한 망·오프라인·개인정보 민감도·오류·캐시·새 버전 전환을 조합하고, 각 발견에 영향 상황 수·심각도·재현 조건·개선안을 쓴다.

반드시 “가상 사용자 상황 분석”, “설계 기반 모의 분석”, “실제 사용자 조사나 고객 설문이 아님”을 함께 쓴다.

## 8. 증거와 진척률

증거는 A 실제 기기, B 자동·응답, C 가상 분석, D 상용화 빈칸으로 분리한다. 시작 전에 가중치 합계 100을 만들고, 실행 진척률과 실행 범위 통과율을 따로 계산한다. PASS·FAIL·PARTIAL·BLOCKED·DEFERRED·UNVERIFIED는 서로 바꿔 쓰지 않는다.

권장 가중치: 기기 식별 10, 공개·대시보드·QR 10, 핵심 실제 흐름 40, 개인정보·오류·복구 10, 접근성 10, 오프라인·복귀 10, 가상 분석 5, 상용화 빈칸 5.

## 9. 결과 보고서

다음 표를 모두 작성한다: 기기 발견 결과, 공개 상태, 실제 기기 검사, 자동·응답 검사, 가상 사용자 상황 분석, 상용화 빈칸, 발생 문제·해결 기록, 진척률, 증거 수준 결론. 실제 기기·자동 검사·가상 분석·상용화 빈칸을 한 문장에 섞지 않는다.

## 10. 최종 실행 지시

지금 `adb devices -l`부터 실행한다. 승인 기기와 다른 작업자 미사용이 확인되면 기기 검사를 계속한다. 하나라도 미확인이면 해당 기기는 DEFERRED로 두고, 공개 URL·QR·자동 검사·가상 분석·상용화 빈칸 검사는 멈추지 않는다. 범위 밖 데이터 추출·보안 우회·기기 설정 변경은 실행하지 않는다.
