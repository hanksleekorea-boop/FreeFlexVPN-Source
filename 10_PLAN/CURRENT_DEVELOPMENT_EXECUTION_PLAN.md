5. 원본을 먼저 수정하고 공식 생성 도구로 결과물을 만든다. `30_DEPLOY`만 직접 고쳐 원본과 어긋나게 하지 않는다.
6. 새 상태는 `loading/empty/ready/stale/partial/error/cancelled/recovery`를 모두 정의한다.
7. 정상 검사와 일부러 틀린 값을 넣어 실패를 잡는 검사를 함께 만든다.
8. 카드의 필수 증거가 없으면 `WAITING-EXTERNAL`로 남기고 다음 독립 작업을 진행한다. 증거를 꾸며 `DONE`으로 바꾸지 않는다.
9. 실제 IP, 기기 일련번호, 계정 원문, 개인키, 설정 원문, 쿠키, 인증 열쇠 문자열을 코드·로그·증거에 저장하지 않는다.
10. 작업 종료 때 대시보드·STATE·HISTORY·TEST_EVIDENCE를 갱신하되 실제 수치가 늘어난 경우에만 점수를 바꾼다.

#### B. 상태 값

- `READY`: 지금 로컬에서 시작 가능
- `PLANNED`: 선행 작업이 남음
- `IN_PROGRESS`: 한 작업자가 현재 수정 중
- `WAITING-EXTERNAL`: 기기·서버·결제·법률·운영 결정이 필요
- `BLOCKED`: 같은 차단이 세 번 확인되고 독립 작업도 없음
- `DONE-CODE`: 코드·자동 검사만 통과
- `DONE-VERIFIED`: 카드가 요구한 브라우저·실기기·결제·전문가·운영 증거까지 모두 통과

단계 종료에는 모든 필수 카드가 `DONE-VERIFIED`여야 한다. `DONE-CODE`를 상용 완료로 세지 않는다.

#### C. 모든 작업에서 실행할 공통 검사

작업 전용 검사를 먼저 실행하고, 성공 뒤 아래 순서로 전체 확인한다.

```powershell
python -X utf8 70_TOOLS/run_all_tests.py --jobs 1 --timeout 120
python -X utf8 70_TOOLS/scan_secrets.py
python -X utf8 70_TOOLS/make_manifest.py --check
git diff --check
```

`make_manifest.py --check`가 기존 미저장 파일 때문에 실패하면 그 실패를 숨기지 말고, 현재 작업이 만든 누락과 기존 누락을 분리한다. 목록표를 임의로 다시 만들지 않는다.

#### D. 작업 완료 영수증 형식

각 작업은 `10_STATE/CC_TASK_<ID>_<YYYY-MM-DD>.json`에 다음 비밀값 없는 필드를 남긴다.

```json
{
  "task_id": "CC-TASK-1-01",
  "status": "done_verified",
  "checked_at": "YYYY-MM-DD",
  "changed_paths": [],
  "preserved_contracts": [],
  "automatic": {"passed": 0, "failed": 0},
  "browser": {"status": "not_run", "viewports": []},
  "device": {"status": "not_run", "platform": null},
  "external": {"payment": "not_run", "legal": "not_run", "operations": "not_run"},
  "unknowns": [],
  "rollback": {"tested": false, "result": "not_run"}
}
```

없는 증거는 `not_run`으로 쓴다. 실제 값 대신 `pass`를 손으로 넣지 않는다.

### 12.5 2단계 상세 작업 카드 — 선두권 플랫폼 확장

#### CC-TASK-2-01 Windows 실제 VPN

공식 Windows WireGuard에서 기기 전용 프로필 발급·가져오기·연결·DNS·IPv4/IPv6·킬 스위치 동등 설정·Wi-Fi 전환·해제 복귀를 실제 검사한다. PC 관리 웹은 Windows 터널 상태의 검증 시각과 미확인 범위를 표시한다. 기존 Android 권리·프로필을 공유 변경하지 않는다. Windows 실기기 증거 전에는 `PC VPN 지원`을 공개하지 않는다.

#### CC-TASK-2-02 iPhone 실제 VPN

지원 iOS 범위를 정하고 공식 WireGuard에서 첫 연결·온디맨드/항상 연결 가능한 범위·DNS·IPv4/IPv6·망 전환·해제 복귀를 검사한다. Android와 같은 계정·사용량·기기 폐기 규칙을 쓰되 플랫폼 차이를 숨기지 않는다. 실제 iPhone 증거 전에는 설치 안내만 제공하고 지원 완료로 표시하지 않는다.

#### CC-TASK-2-03 다지역·혼잡·자동 대체

실제 검증된 지역만 서버 목록에 넣고 `available/degraded/full/maintenance/unknown` 상태, 측정 시각, 용량, 대체 경로를 운영 자료와 연결한다. 자동 선택은 기본적으로 추천만 하고 사용자가 확정한다. 오래된 상태로 국가·속도·성공을 만들지 않는다. 지역 장애 시 기존 연결과 잔액을 보존한다.

#### CC-TASK-2-04 개인화·기기 간 연속성

공용 Wi-Fi, 여행, 업무, 수동 프로필을 사용자가 선택해 저장한다. 자동 연결은 기본 꺼짐, 규칙별 설명·취소·기기별 적용 범위를 제공한다. 모바일·PC·iPhone·Windows가 같은 계정 자료를 보더라도 개인키는 동기화하지 않는다. 설정 충돌·오래된 판·오프라인 변경을 검사한다.

#### CC-TASK-2-05 Kakao Connect 제한 파일럿

K0~K4 후보를 기존 WireGuard 경로와 분리한 채 유휴 Android 한 대에서 실제 카카오톡·LINE·음성/영상 통화·일반 웹·DNS·복귀를 검사한다. 중국망·검열 성공·가격·VLESS/REALITY·Hysteria2는 실제·법률·비용 증거가 없으면 계속 연구 후보로 둔다. 실패해도 기존 `ffvpn`, 무료량, 충전, 추천, 공개 URL을 바꾸지 않는다.

#### CC-TASK-2-06 독립 감사·신뢰센터 고도화

1단계 출시 범위와 2단계 새 플랫폼을 제3자가 검토하고, 범위·방법·발견·심각도·조치·재검증·남은 위험을 신뢰센터에 공개한다. 서버 수·사용자 수·장애·법적 요청·자료 처리 범위를 실제 운영값으로 정기 갱신한다. 마케팅 문구가 보고서 범위를 넘어가지 않게 자동 대조한다.

#### CC-TASK-2-07 2단계 선두권 판정

Windows·iPhone·다지역·개인화·Kakao 파일럿·감사의 필수 증거를 모아 플랫폼별로 판정한다. Kakao가 미통과여도 1단계와 Windows/iPhone 일반 VPN을 낮추지 않고 `연구 중`으로 분리할 수 있다. 새 플랫폼의 치명·높음 결함 0과 1단계 전체 재검사 통과가 종료 조건이다.

### 12.6 3단계 상세 작업 카드 — 세계 최고 후보

#### CC-TASK-3-01 1·8·24시간 성능·배터리

지원 플랫폼·통신망·지역 조합에서 연결 시간, 끊김, 재연결, 처리량, 지연, 배터리, 발열, 데이터 사용을 1/8/24시간 측정한다. 기기·망별 표본 수와 측정 한계를 공개하고 최고값만 고르지 않는다. 성능 개선 때문에 킬 스위치·개인정보·무료 권리를 낮추지 않는다.

#### CC-TASK-3-02 안전한 장애·검열 대체 연구

#### CC-TASK-3-03 운영 자동화·재해 훈련
