# FreeFlexVPN 상용화 출시 관문 계획 v1.0

> 이 파일은 현재 서비스 기획과 상세 개발실행계획을 대체하지 않는다. 2026-08-10부터 실제 고객에게 안전하게 제공하기 위한 **우선순위 조정 정본**이다. 기존 F0~F6 화면 묶음은 이 관문을 통과하는 데 필요한 순서로 실행한다.

## 서비스 요약

FreeFlexVPN은 공용망·여행 중 사용자가 공식 WireGuard 앱으로 안전한 인터넷 통로를 쓰도록 돕는 서비스다. 현재는 화면·자동 검사·실제 서버와 Android용 설정 1개가 있는 시험 서비스이며, Android 실제 터널·IPv4·DNS·재연결은 확인했다. IPv6·차단 모드·외부 경로 일치, 결제·고객지원은 아직 미확인이다.

## 원칙

1. 화면이 보여도 실제 서버·실기기 증거가 없으면 상용 가능이라고 쓰지 않는다.
2. 비용·개인정보·외부 공개·실기기 설정 변경은 현재 대화의 승인 범위 안에서만 한다.
3. 비밀키·원본 설정·실제 IP·계정 정보는 문서·대시보드·Git에 기록하지 않는다.
4. 한 관문의 필수 조건이 하나라도 미확인이면 다음 관문으로 넘어가지 않는다.
5. 자동 검사, 실제 PC, 실제 Android, 가상 페르소나, 실제 고객 의견은 서로 다른 증거로 기록한다.

## G0 — 비용·권한 (가장 먼저)

1. Cloud Shell Google 인증을 완료한다.
2. 올바른 프로젝트, 결제 연결, 현재 VM·고정 IP, Compute 사용 가능 상태를 읽기 전용으로 확인한다.
3. VM·디스크·고정 IP·예상 송신 비용을 합쳐 월 USD 10 안에 드는지 계산한다.
4. 예산 알림은 지출을 자동으로 멈추지 않는다는 점을 기록한다.
5. 월 USD 10을 보장할 수 없으면 서버를 만들지 않고, 더 낮은 비용 대안 또는 사용량 제한안을 제시한다.

**통과 증거:** 값은 숨긴 요약으로만 기록하고, 계정·결제·실제 IP·열쇠 문자열은 남기지 않는다.

## G1 — 실제 VPN과 Android 검사

1. G0 통과 뒤 최소 서버 한 대를 만든다.
2. WireGuard·방화벽·IPv4 전달·DNS·사용량 제한 서비스를 서버 안에서 확인한다.
3. 서버 공개키만 확인하고, 개인키·기기 설정 원문은 기록하지 않는다.
4. Android 전용 설정을 안전하게 발급한다.
5. Android에서 가져오기 → VPN 연결 요청 → 연결 → 외부 경로 일치·DNS·IPv6·차단 모드 → 끊김 뒤 재연결 순으로 검사한다. 현재 가져오기·권한·터널·IPv4·DNS·재연결은 실제 통과했다.
6. IPv6이 도달하지 않거나 차단 모드·외부 경로 일치가 미확인이면 보호됨 표시는 유지하지 않고 원인을 기록한다.

**통과 증거:** 실제 Android 검사 결과와 자동 검사 결과를 분리해 기록한다. 현재 증거는 `10_STATE/FREEFLEXVPN_PUBLIC_DEVICE_QA_v1_1_2026-08-10.md`에 있으며, 개인 설정·실제 IP 값은 기록하지 않는다.

### G1-R — 기존 Android 프로필 안전 교체 절차

기존 `ffvpn`은 삭제·덮어쓰기·자동 활성화하지 않는다. 별도 검증 프로필의 성공 기록은 기존 프로필의 오류를 해결했다는 뜻이 아니며, 둘을 같은 증거로 합치지 않는다.

1. **읽기 전용 비교:** 서버에서는 피어 개수·최근 악수 유무·전달/NAT/방화벽 상태만, 기기에서는 터널 이름·켜짐 여부·항상 연결·차단 모드만 확인한다. 개인키·설정 원문·실제 IP는 읽거나 기록하지 않는다.
2. **교체 후보 분리:** 기존 프로필을 보존한 채 새 검증 프로필만 후보로 둔다. 새 프로필이 실제 DNS·일반 웹·서버 악수·끔 뒤 일반망 복귀를 모두 통과할 때까지 기존 프로필 상태를 바꾸지 않는다.
3. **사람 확인 뒤 1회 전환:** 다른 자동화가 기기를 사용하지 않을 때만 사람이 공식 WireGuard 앱에서 후보 프로필을 직접 켠다. 웹앱·ADB는 항상 연결·차단 모드를 대신 켜지 않는다.
4. **판정:** 후보가 네 가지 증거를 모두 통과하면 `후보 연결 통과`로만 기록한다. IPv6·외부 경로 일치·차단 모드·iPhone은 별도 미완료로 남긴다. 하나라도 실패하면 후보를 끄고 기존 프로필을 보존하며 원인만 기록한다.
5. **되돌리기:** 인터넷이 비정상으로 보이면 후보·항상 연결·차단 모드를 모두 끈 상태로 돌아가 일반망 DNS와 웹 표시만 다시 확인한다. 기존 프로필 삭제·서버 피어 폐기는 사용자 확인 전 금지한다.

**G1-R 통과 조건:** 읽기 전용 비교 기록, 사람 직접 전환 1회, DNS·일반 웹·서버 악수·일반망 복귀의 분리된 실제 증거, 기존 프로필 보존, 비밀값 0개 기록.

**2026-08-12 구현 상태:** 웹앱은 새 후보를 첫 활성 기기와 섞지 않고 검사 대상으로 유지한다. 후보의 터널·외부 경로·서버 악수·DNS가 모두 확인되고, 사람이 후보를 끈 뒤 일반 웹 복귀를 별도로 확인하기 전에는 기존 설정 폐기를 비활성화한다. 마지막 폐기는 되돌릴 수 없음 확인을 한 번 더 거치며, 기기 목록에는 할당 주소·키를 표시하지 않는다. 자동 Chromium 왕복과 음성 대조는 통과했지만 실제 Android 사람 전환 증거가 없으므로 G1-R 자체는 아직 미통과다.

**2026-08-14 읽기 전용 판정 보강:** 민감정보 없는 기기·서버 상태만 받는 `profile_reissue.py`와 CLI를 추가했다. 과거 별도 프로필 성공, 현재 live readback, 기기/서버 후보 불일치, 후보 실패, 별도 후보 발급 검토, 기존 피어 폐기 검토를 서로 다른 상태로 판정한다. 모든 결과에서 기존 프로필은 보존되고 실제 mutation은 0이다. 현재 환경은 ADB 도구와 서버 live readback이 없어 `readback_required`; G1-R은 아직 미통과다.

## G2 — 고객 핵심 흐름

1. QR을 못 읽음, 카메라 거부, 만료 설정, 빈 파일, 형식 오류의 복구 경로를 실제 Android에서 확인한다.
2. 새 기기 추가, 기기 해지, 분실 기기, 재발급의 영향과 되돌릴 수 없음 안내를 확인한다.
3. PC↔폰 QR은 서비스 주소와 VPN 설정 QR을 명확히 구분한다.
4. iPhone은 실제 기기 확인 전까지 안내 제공·미검증 상태로 남긴다.

## G3 — 보안·개인정보

3. 서버 관리 접근은 최소 권한, 강한 인증, 변경 기록, 긴급 접근 절차를 갖춘다.
4. 취약점 신고·수정·공개 절차를 `SECURITY.md`와 지원 문서에 연결한다.

## G4 — 품질·접근성

1. 모바일 390px와 PC 1280px·1920px에서 같은 정보 순서와 도달 경로를 확인한다.

3. 느린 망·오프라인·API 오류에서 가짜 정상 상태 대신 다음 행동을 보여 준다.

## G5 — 운영·지원

3. 새 공개 버전은 검사 통과 뒤 기존 공개 URL에만 반영한다.
4. 독립 운영 감시와 백업·복구는 실제 동작 증거가 생기기 전까지 미확인으로 표시한다.

## G6 — 결제·악용 방지

1. 실제 결제·환불·영수증·세금은 별도 비용·개인정보·공개 승인 뒤에만 시작한다.
2. 사용량 제한·충전·추천 보상은 실제 원장과 일치하는지 확인한다.
3. 스팸·P2P·대량 사용·계정 남용 대응은 과장 없이 서비스 정책으로 공개한다.
4. 결제 정보를 서비스·Git·대시보드에 보관하지 않는다.

## G7 — 제한 공개와 출시 판정

1. G0~G6의 필수 조건 전부를 증거와 함께 다시 확인한다.
2. 제한 공개 범위, 사용자 수, 지원 시간, 운영 책임자를 명시하고 현재 대화에서 공개 승인을 받는다.
3. 출시 뒤 실제 장애·비용·사용량·지원 요청을 관찰하되 개인정보 최소화 원칙을 지킨다.
