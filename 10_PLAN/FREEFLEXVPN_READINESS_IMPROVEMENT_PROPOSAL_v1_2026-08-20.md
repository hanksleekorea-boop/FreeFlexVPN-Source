## 1. 제안 한 줄

FreeFlexVPN을 “화면과 자동 검사가 갖춰진 VPN/PWA 후보”에서 “실제 연결·안전·운영·상용 조건을 증거로 설명할 수 있는 서비스”로 올리되, 기존 WireGuard 기본 경로와 카카오 특화 비하향 계약을 절대 낮추지 않는다.

## 3. 비하향 계약

이 제안은 `10_PLAN/KAKAOVPN_NON_REGRESSION_CONTRACT_v1.json`의 하한을 유지한다.

- 월 무료 1GB, 무기한 충전, 자동결제 없음, 기존 추천 원장·보상 규칙을 낮추지 않는다.
- WireGuard를 기본 경로로 유지하고, 연구 경로는 실제·법률 증거 전까지 격리된 연구 후보로 둔다.
- 기존 공개 앱·PC 주소·서비스 QR과 모바일 접근성, 큰 글씨·고대비·키보드/화면읽기 기준을 유지한다.
- 기존 Android `ffvpn`과 다른 기존 프로필은 삭제·덮어쓰기·자동 활성화하지 않는다.
- 개인키·원본 구성·실제 IP·원문 목적지/접속 기록·인증 열쇠 문자열을 문서·화면·저장 기록에 넣지 않는다.
- Drive B는 연결·구성·읽기·쓰기·복제·복원·삭제 대상에서 영구 제외한다.

## 5. 작업 흐름 A — 실제 연결과 안전 증거

목적: 사용자가 보는 연결·보호 표기와 실제 네트워크 상태를 일치시킨다.

1. 대상 GCP 서버를 식별값·키·실제 IP를 저장하지 않는 읽기 전용 검사로 다시 확인한다.
2. 기존 프로필과 분리된 **새 검증 후보만** 준비 가능 여부를 판정한다. 대상이 불명확하면 변경하지 않고 `target_not_accessible`을 유지한다.
3. 유휴 상태가 확인된 Android 정확히 한 대에서만 후보를 사람이 직접 켠다.
4. 터널, DNS, 일반 웹, 서버 악수, 외부 경로 일치, IPv6 상태, 연결 해제 뒤 일반망 복귀를 각각 분리해 기록한다.
5. 차단 모드는 인터넷 단절 영향을 사전 고지하고, 별도 확인 조건 아래에서만 다룬다.

통과 조건: 비밀값 없이 각 검사가 분리된 실제 증거를 남기고, 기존 `ffvpn` 보존과 일반망 복귀가 확인돼야 한다. 어느 하나라도 실패·미확인이면 `protected` 범위를 늘리지 않는다.

## 6. 작업 흐름 B — 제품 신뢰·접근성·복구

목적: 연결 실패와 불안정망에서 사용자가 1분 안에 다음 행동을 찾게 한다.

- 실제 확인/미확인/준비 중 상태 문구를 하나의 상태 모델에서 관리한다.
- QR·파일·카메라 거부·만료·재연결·분실 기기의 복구 경로를 화면·FAQ·가린 진단에서 같은 내용으로 제공한다.
- 360/390/768/1280/1920 폭, 200% 확대, 키보드, 화면읽기, 저속망·오프라인을 각각 검사한다.
- 새로고침·뒤로가기·공유에서 상태가 왜곡되지 않는지 확인한다.
- 가상 페르소나 1,000명으로 온보딩, 가격 이해, 오류 복구, 기존 설정 보존의 가설을 반복 확인한다.

통과 조건: 자동 검사와 가상 결과는 [확인] 또는 [추정]으로 구분하고, 실제 고객 조사라고 표현하지 않는다.

## 7. 작업 흐름 C — 보안·개인정보·운영

목적: VPN 서비스를 안전하게 설명하고 장애 때 책임 있는 다음 행동을 제공한다.

- 인증·인가, 권한 분리, 감사 기록, 비밀값 관리, 의존성 취약점 점검을 위협 모델과 함께 정리한다.
- HTTPS/TLS, 보안 헤더, 깨진 링크, 공개 배포 결과를 외부에서 다시 확인한다.
- 개인정보 수집/미수집, 보유·파기, 삭제·내보내기, 위탁·국외 이전, 권리 요청의 실제 처리 흐름을 법률 검토 전후로 분리한다.
- 운영자 신원, 지원 채널, 응답 기준, 장애 공지, 긴급 중지와 이전 판으로 되돌리기(롤백) 연습을 운영 문서에 연결한다.

통과 조건: 법률 자문·외부 보안 검토·실제 운영 리허설 없이는 완료·준수 인증으로 표시하지 않는다.

## 8. 작업 흐름 D — 결제·상용 운영

목적: 유료 전환을 할 경우 사용자가 가격·환불·영수증·제한을 오해하지 않게 한다.

- 사업자가 가격·체험 한도·결제수단·자동결제 여부·환불·세금·영수증의 정책을 먼저 확정한다.
- 그 뒤 PG 또는 IAP의 시험 거래에서 결제 성공·실패·중복·취소·환불·영수증·정산을 종단 검증한다.
- 정기결제·총액·다크패턴 금지·미성년자/국외 결제 같은 항목은 적용 여부를 명시하고, 제외 근거를 남긴다.
- 제한 공개는 사용자 수·지원 시간·비용 상한·중지 조건·관찰 지표가 정해진 뒤에만 시작한다.

통과 조건: 실제 금전·세금·법률 변경은 이 문서의 채택만으로 자동 실행하지 않으며, 사업자 결정과 별도 안전 확인 뒤에만 시행한다.

## 10. 증거와 점수 규칙

- [확인]은 실제 실행·측정·외부 응답·자동 검사의 원본 증거가 있을 때만 쓴다.
- [추정]은 코드·문서·가상 페르소나·모델 계산에만 쓴다.
- [미확인]은 법률, 실제 결제, 운영 SLA, 외부 보안 검토, 대상 서버, 실기기에서 증거가 없을 때 유지한다.
- 자동 검사, 브라우저 검사, 실제 Android, 실제 Windows, 가상 1,000명, 실제 고객 피드백은 서로 대체하지 않는다.
- 점수는 증거가 증가한 뒤에만 바꾸며, 이 계획의 채택 자체로 수치를 올리지 않는다.

## 11. 완료 정의

이 제안의 “계획 반영 완료”는 문서가 통합되고 링크·용어·통과 조건이 서로 모순되지 않는 상태를 뜻한다. “상용 운영 완료”는 별도이며, 실제 VPN·Android/PC/iPhone 범위·결제/환불·법률·운영·제한 공개 관문을 모두 증거로 닫은 뒤에만 판정한다.
