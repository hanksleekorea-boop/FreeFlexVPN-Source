## 0. 이 기획안의 결론

FreeFlexVPN이 선두권과의 격차를 가장 빨리 줄이는 길은 NordVPN처럼 기능 수와 국가 수를 한꺼번에 늘리는 것이 아니다. **Mullvad의 개인정보 최소화, Proton VPN의 검증 가능한 보호·공개 신뢰, ExpressVPN의 쉬운 연결·복구**를 기준으로 삼아, FreeFlexVPN의 강점인 **비구독형 무기한 충전·증거 결속 보호 카드·안전한 기기 수명주기**를 실제 운영 증거로 완성해야 한다.

첫 상용 범위는 `지원 Android + 공식 WireGuard + 모바일·PC 관리 웹 + 검증된 최소 노드`로 좁힌다. 이 범위 안에서는 연결, 누출 방지, 장애 복구, 결제, 환불, 삭제, 지원까지 완결한다. iPhone·Windows·다국가·검열 우회·Kakao Connect는 1단계 상용판을 늦추지 않는 별도 확장선으로 둔다.

핵심 목표는 한 문장이다.

> **사용자가 3분 안에 실제 보호 상태를 확인하고, 문제가 생기면 1분 안에 다음 안전 행동을 찾으며, 결제·환불·삭제·장애까지 근거로 확인할 수 있는 가장 정직한 비구독형 여행 VPN을 만든다.**

이 문서를 채택하는 것만으로 점수나 완료 상태는 올라가지 않는다. 아래 통과 증거가 생긴 뒤에만 대시보드 수치를 바꾼다.

1. **보호 사실 격차**: 터널이 켜졌다는 표시와 DNS·IPv6·WebRTC·차단·경로의 실제 결과가 한 증거로 묶이지 않았다.
2. **운영 신뢰 격차**: 서버 상태, 장애 공지, 대응 시간, 이전 판 복귀, 백업 복구, 외부 보안 검토가 실제로 운영되지 않는다.
3. **상용 거래 격차**: 가격·세금·결제·중복·취소·환불·영수증·삭제가 실제 왕복으로 검증되지 않았다.
4. **범위 격차**: 선두권은 여러 운영체제와 많은 지역을 지원하지만 FreeFlexVPN은 Android 한 대·한 경로의 부분 증거만 있다.

화면 기능을 추가하는 것만으로 1~3번은 닫히지 않는다. 따라서 모든 작업은 `코드 존재 → 자동 검사 → 브라우저 확인 → 실기기/운영/실거래 확인` 순으로 승격한다.

## 3. 목표 체계

### 3.1 최상위 성과 지표

1. **검증된 보호 세션 비율(VPSR)**: 지원 환경에서 터널·외부 IPv4·DNS·신선도가 함께 통과한 세션 / 연결 시도 세션.
2. **보호 확인까지 걸린 시간(TTVP)**: 사용자가 시작을 누른 때부터 `보호 확인됨`을 보는 때까지.
3. **알려진 오류의 안전 복구율(SRR)**: 60초 안에 연결 복구 또는 안전 중단·일반망 복귀·지원 연결로 끝난 비율.
4. **권리 원장 정확도(LAI)**: 무료·추천·충전 사건 중 중복 차감·유실·잘못된 만료가 없는 비율.
5. **고객 신뢰 완료율(TCR)**: 가격 확인→결제/무료 시작→환불/삭제/문의 중 선택 과업을 끝낸 비율.

### 3.2 단계 목표 — 모두 목표값이며 현재 성과가 아님

| 지표 | 제한 출시 통과 목표 | 선두권 추격 목표 | 증거 방법 |
|---|---:|---:|---|
| 신규 사용자 TTVP 중앙값 | 3분 이하 | 90초 이하 | 처음 쓰는 실제 사용자 과업 기록 |
| 신규 사용자 TTVP 90백분위 | 5분 이하 | 3분 이하 | 최소 30개 실제 과업 |

| DNS/IPv6/WebRTC 심각 누출 | 0건 | 0건 | 지원 환경 시험표와 일부러 틀린 구성 검사 |

## 4. 제품·기술 구조의 기준

### 4.1 세 평면 분리

- **데이터 평면**: WireGuard 터널, DNS, IPv4/IPv6, 서버 경로. 실패가 곧 보호 실패다.
- **제어 평면**: 설정 발급·만료·재발급·폐기, 기기 판번호, 권한. 다른 기기나 기존 프로필을 손상시키면 안 된다.
- **증거 평면**: 보호 검사, 서버 상태, 사용량, 결제·삭제 영수증, 공개 판번호. 오래되거나 빠진 증거는 성공으로 보이면 안 된다.

세 평면은 같은 화면을 사용해도 독립 실패 상태를 가진다. 예를 들어 터널이 연결돼도 DNS 증거가 없으면 `연결됨, 보호 확인 불가`로 표시한다.

### 4.2 모든 자료의 공통 상태

`loading`, `empty`, `ready`, `stale`, `partial`, `error`, `cancelled`, `recovery`를 유지한다. 각 자료는 아래 공통 필드를 가진다.

| 필드 | 뜻 |
|---|---|
| `evidence_id` | 비밀값 없는 증거 식별자 |
| `subject_scope` | 세션·기기·계정·노드 등 적용 범위 |
| `observed_at` | 실제 관찰 시각 |
| `expires_at` | 성공 표현을 유지할 수 있는 시각 |
| `source_class` | 자동·브라우저·실기기·실거래·운영·전문가 |
| `result` | pass·fail·partial·unknown |
| `redaction` | 제거한 개인정보·비밀값 종류 |
| `version` | 앱·API·노드·정책 판번호 |

## 5. 격차를 압축하는 7개 프로그램

### GCP-1. 검증된 보호 핵심

**목표:** Proton·Mullvad·PIA 수준을 참고해, 지원 Android에서 `보호됨`이 실제 네트워크 결과와 일치하게 한다.

필수 기능:

1. 연결 전후의 외부 IPv4 국가/노드 일치 확인. 실제 주소 원문은 저장하지 않는다.
2. DNS 질의 경로·IPv6 도달 가능 여부·WebRTC 노출을 분리 검사한다.
3. 항상 연결·VPN 없는 연결 차단·Wi-Fi↔이동통신·재부팅·비행기 모드 뒤 복귀를 시험한다.
4. 증거가 하나라도 오래되거나 빠지면 `부분 보호` 또는 `확인 필요`로 낮춘다.
5. 사용자가 보호 확인을 취소하거나 실패해도 기존 프로필을 삭제하지 않는다.
6. 지원하지 않는 IPv6 환경은 `차단됨`, `미지원`, `미확인`을 구분한다.

통과 증거:

- 유휴 Android 정확히 한 대에서 정상·DNS 실패·서버 불가·망 전환·재부팅·차단 모드·복귀를 분리 기록한다.
- 최소 50회 반복 연결에서 실패 원인과 성공률을 남긴다. 50회 무결함은 보편적 무결함을 뜻하지 않는다.
- 서버 악수·클라이언트 보호 카드·외부 경로 검사의 관찰 시각 오차를 허용 범위 안으로 맞춘다.

기존 연결: `CC-TASK-1-01`, `1-02`, `1-03`, `1-04`, `1-14`.

### GCP-2. 3분 첫 연결·1분 복구

**목표:** ExpressVPN·TunnelBear의 쉬운 시작을 참고하되, 공식 WireGuard를 사용하는 현재 구조 안에서 초보자가 막히지 않게 한다.

필수 기능:

1. 시작 화면에는 `지원 기기`, `무료 1GB`, `자동 갱신 없음`, `수집 정보`, `실제 제공 위치`를 먼저 표시한다.
2. 같은 휴대폰에서는 서비스 QR 대신 1회성 설정 파일과 공식 앱 열기 안내를 우선한다.
3. PC→휴대폰에서는 서비스 주소 QR과 개인 설정 QR을 색·제목·경고로 구분한다.
4. 설정은 발급 뒤 짧은 시간 한 번만 노출하고, 만료·취소·재발급 상태를 분리한다.
5. 대표 오류 8종은 `무슨 일·자료 영향·지금 할 한 행동·지원`의 동일한 문법을 쓴다.
6. 재시도는 상한을 두고, 결제·폐기·삭제는 자동 재시도하지 않는다.

대표 오류 8종: 인터넷 없음, 서버 불가, DNS 실패, 권한 거부, 설정 만료, 설정 가져오기 실패, 잔액 부족, 증거 오래됨.

통과 증거:

- 처음 쓰는 실제 사용자 최소 5명으로 문구와 경로를 먼저 관찰하고, 제한 출시 전에 최소 30개 과업으로 확대한다.
- 중앙값 3분, 90백분위 5분, 대표 오류의 60초 안전 종료 90%를 목표로 한다.
- 실제 사용자가 없을 때는 1,000명 가상 여정으로 위험을 찾되 성과로 계산하지 않는다.

기존 연결: `CC-TASK-1-02`, `1-03`, `1-11`.

### GCP-3. 개인정보 최소화·공개 신뢰

**목표:** Mullvad·IVPN·Proton의 최소 계정·공개 검토 방식을 참고해 작은 사업자의 신뢰 약점을 줄인다.

필수 기능:

1. 무작위 계정 번호 또는 최소 식별을 기본으로 하고 이메일은 복구·영수증에 필요할 때 선택 받는다.
2. 개인키는 가능한 한 기기에서 만들고, 서버·지원·분석·화면에 원문을 남기지 않는다.
3. 방문 목적지, DNS 원문, 실제 IP, 설정 원문을 수집하지 않는 범위와 예외를 사실표로 공개한다.
4. 자료별 보유 기간·삭제 방법·법정 보관·처리자·국외 이전을 한 표로 공개한다.
5. 계정 내보내기·기기 폐기·계정 삭제의 부분 실패까지 영수증으로 보여 준다.
6. 코드 공개 범위, 독립 보안 검토 범위, 발견·수정·남은 위험을 신뢰센터에 연결한다.

통과 증거:

- 실제 시험 계정의 내보내기·부분 삭제·전체 삭제·법정 보관 예외 왕복.
- 외부 보안 검토에서 높은 위험 0, 수정 항목의 재검증 완료.
- `무로그` 표현은 실제 운영 자료와 독립 검토가 일치할 때만 제한적으로 사용한다.

기존 연결: `CC-TASK-1-07`, `1-10`, `1-12`, `2-06`.

### GCP-4. 비구독형 권리 지갑·투명 거래

**목표:** Proton·Windscribe·TunnelBear의 무료 진입 장점과 Mullvad·IVPN의 단순 가격을 참고하되, FreeFlexVPN만의 `월 무료 1GB + 무기한 충전 + 자동 갱신 없음`을 명확한 차별점으로 만든다.

필수 기능:

1. 무료·추천·충전 잔액, 차감 순서, 측정 시각, 근거 사건을 분리한다.
2. 동일 사건은 여러 번 도착해도 한 번만 차감한다.
3. 무료량만 월 경계에서 갱신하고 충전·추천은 운영자가 확정한 권리대로 보존한다.
4. 결제 전에 총액·세금·통화·자동 갱신 없음·환불·결제 사업자를 표시한다.
5. 성공·실패·중복·취소·환불·구매 복원·잔액 반영 지연을 실제 시험 거래로 검증한다.
6. 결제와 잔액 반영이 어긋나면 `검토 중`으로 닫고 임의 재결제하지 않는다.

통과 증거:

- 실서버 계수와 원장 표본 대조, UTC 월 경계, 동시 사건, 재처리, 장애 복구 통과.
- 실제 시험 거래 7종과 영수증·환불 자료 대조.
- 가격·세금·환불은 운영자와 법률/세무 확인 전 `unresolved` 유지.

기존 연결: `CC-TASK-1-06`, `1-08`.

### GCP-5. 서버 신뢰·장애 운영

**목표:** ExpressVPN·CyberGhost의 지원 운영과 Proton·Mullvad의 기술 투명성을 참고해, 작은 노드 수를 정직한 상태·빠른 복구로 보완한다.

필수 기능:

1. 공개 노드마다 실제 가용성, 마지막 확인 시각, 용량 경고, 장애 상태를 제공한다.
2. 상용 출시 전 최소 두 개의 독립 장애 범위를 가진 노드가 필요하다. 비용과 구조 가능성은 별도 확인한다.
3. 노드 장애 시 자동 강제 전환보다 사용자의 명시 선택과 자료 영향 설명을 우선한다.
4. 장애 인지→상태판 공지→복구→사후 기록의 시각을 남긴다.
5. 백업 복구, 비밀값 교체, 긴급 중지, 이전 판 복귀를 분기별로 연습한다.
6. 지원 채널, 실제 운영 시간, 첫 답변 목표, 장애 보상 범위를 공개한다.

통과 증거:

- 노드 중지, DNS 장애, 잘못된 설정, 공개판 오류를 일부러 만들어 경보와 안전 복귀를 확인한다.
- 상태 자료가 오래되면 `정상` 대신 `확인 지연`으로 보인다.
- 최소 한 번의 운영 훈련에서 탐지·공지·복구·회고가 모두 남는다.

기존 연결: `CC-TASK-1-09`, `1-13`, `1-14`, `1-15`.

### GCP-6. 플랫폼·기기 확장

**목표:** Surfshark·PIA의 여러 기기 편의와 선두권의 Android·iPhone·Windows 지원을 단계적으로 따라잡는다.

순서:

1. Android + 공식 WireGuard + 관리 웹을 완전 상용화한다.
2. Windows 공식 WireGuard 실제 흐름을 추가하고 PC 웹과 상태를 연결한다.
3. iPhone 공식 WireGuard 실제 흐름을 추가한다.
4. 자체 Android/iOS 앱은 사용자 이탈 원인과 지원 비용이 공식 앱 방식의 한계를 넘어설 때만 개발한다.
5. 자체 앱을 만들 경우 WireGuard 코드 사용 조건, 앱마켓 정책, 키 저장, 차단 모드 구현을 독립 검토한다.
6. 다중 기기 목록은 표시 이름·판번호·최근 확인·분실 폐기만 보여 주고 주소·키 원문을 숨긴다.

통과 증거:

- 각 운영체제에서 발급→가져오기→연결→누출→망 전환→차단→해제→일반망 복귀를 별도 통과한다.
- 한 기기 폐기가 다른 기기와 기존 프로필을 손상시키지 않는다.
- 지원하지 않는 플랫폼은 화면에서 `지원 예정`과 `검증 완료`를 혼동하지 않는다.

기존 연결: `CC-TASK-1-05`, `2-01`, `2-02`, `2-03`.

### GCP-7. 선두권과 다른 증거 중심 경험

**목표:** 서버 수를 따라잡기 어려운 초기 단계에서 FreeFlexVPN만의 구매 이유를 만든다.

차별 기능:

1. **보호 영수증**: 주소 원문 없이 터널·경로·DNS·시각·신선도를 한 카드에 표시.
2. **권리 영수증**: 무료·추천·충전의 발생·차감·남은 권리를 설명.
3. **복구 영수증**: 실패 원인, 시도한 조치, 일반망 복귀, 남은 미확인을 표시.
4. **기기 안전 영수증**: 발급·재발급·폐기 영향과 다른 기기 무손실을 표시.
5. **정직한 국가 카드**: 실제 시험 망·시각·지원 범위·법률 확인 상태를 분리.
6. **Kakao Connect 격리**: 실제망·법률·비용 통과 전에는 연구 후보이며 기본 꺼짐.

선두권과의 차별점은 “더 많은 기능”이 아니라 “내 보호와 권리가 왜 그렇게 표시되는지 증거를 이해할 수 있음”이다.

기존 연결: `CC-TASK-1-01`, `1-06`, `1-12`, `2-04`, `3-05`.

### 6.2 PC 작업대

PC 웹은 Windows VPN인 것처럼 보이면 안 된다. 한 화면에서 다음 다섯 열을 비교한다.

1. 현재 보호와 증거 신선도
2. 기기·프로필 수명주기
3. 권리 지갑·결제·환불
4. 서버 상태·장애·대체
5. 지원·신뢰센터·삭제

### 6.3 공통 문장 규칙

- `보호됨`: 지원 범위의 필수 증거가 모두 최신일 때만.
- `연결됨, 보호 확인 불가`: 터널은 있으나 외부 경로 또는 DNS 증거가 없음.
- `부분 보호`: 일부 보호는 확인됐으나 누출 또는 지원 범위가 남음.
- `보호 안 됨`: 명시적 실패 또는 차단 해제 상태.
- `확인 지연`: 상태 자료가 정한 신선도 시간을 넘음.

### 단계 A — 증거 전환판

목적: 이미 만든 `DONE-CODE`를 실제 검증 가능한 한 묶음으로 연결한다.

- 실제 가격·법률·운영 값은 빈 값으로 유지한다.

종료 조건: 자동·브라우저 결과와 실기기·운영 미확인이 화면에서 섞이지 않고, 다음 실제 시험표가 고정돼야 한다.

### 단계 B — Android 제한 상용판

목적: 지원 범위 안에서 가입부터 환불·삭제·장애까지 실제 왕복을 닫는다.

- GCP-1~5를 모두 통과한다.
- 동의한 제한 고객으로만 시작하고 사용자 수·비용·지원 시간·중지 조건을 고정한다.
- 치명·높음 결함 0, 운영자 출시 서명, 법률·결제 확인 뒤에만 유료를 연다.

종료 조건: 기존 `CC-GATE-1` 18개를 모두 `DONE-VERIFIED`로 통과한다.

### 단계 C — 선두권 플랫폼 확장

목적: Windows·iPhone·여러 지역·독립 검토를 추가한다.

- Windows와 iPhone을 각각 별도 출시 단위로 처리한다.
- 같은 지역 이중 노드 안정성을 먼저 만들고 이후 수요 순으로 지역을 늘린다.
- 국가별 지원 카드는 실제 망·법률·비용 근거가 있을 때만 공개한다.

종료 조건: 지원한다고 표시한 각 플랫폼·지역이 동일한 보호·복구·삭제·지원 증거를 가져야 한다.

### 단계 D — 세계 최고 후보

목적: 장시간 안정성, 투명성 보고, 증거 영수증, 비구독 권리 지갑을 실운영 결과로 차별화한다.

- 1/8/24시간, 여러 통신망, 노드 장애, 공개판 복귀를 정기 시험한다.
- 외부 보안 검토와 투명성 보고를 반복한다.
- 같은 과업·같은 근거 등급으로 직접 VPN 10개와 재비교한다.

종료 조건: 뒤처진 분야는 실제 증거로 동등 이상이거나, 지원하지 않는 이유와 다음 검증일이 공개돼야 한다.
