## 0. 이 문서를 사용하는 방법

이 문서는 낮은 숙련도의 AI도 추측 없이 한 작업씩 수행하도록 만든 실행 설명서다. 한 번에 여러 카드를 개발하지 않는다.

1. 8절 상태표에서 선행 작업이 끝난 가장 작은 번호를 고른다.
2. 해당 카드의 `먼저 읽기` 파일만 읽는다.
3. `수정 허용`에 적힌 파일만 바꾼다. 다른 파일 변경이 꼭 필요하면 카드 영수증에 이유를 먼저 기록한다.
4. 기존 코드가 있으면 새로 만들지 말고 카드의 `기존 자산`을 확장한다.
5. 정상 입력과 일부러 틀린 입력을 모두 검사한다.
6. 자동 검사까지만 통과하면 `DONE-CODE`, 실기기·실거래·운영·전문가 증거까지 있어야 `DONE-VERIFIED`다.
7. 점수는 증거가 늘었을 때만 바꾼다. 문서·코드·검사 수가 늘었다는 이유로 올리지 않는다.

## 1. 제품 범위

### 1.1 1단계 판매 범위

- 지원 Android 판
- 공식 WireGuard 앱
- 모바일·PC 반응형 관리 웹
- 실제 검증된 노드와 지역만 표시
- 월 무료 1GB, 추천 권리, 무기한 충전
- 실제 가격·결제·취소·환불·영수증
- 계정 자료 내보내기·기기 폐기·계정 삭제
- 고객 상태판·문의·장애·복구

1단계에서 iPhone·Windows 실제 VPN, 자체 VPN 앱, 다국가 자동 선택, Kakao Connect 상용판을 지원한다고 표시하지 않는다.

### 1.2 완료의 의미

- `DONE-CODE`: 구현·자동 검사·필요한 브라우저 검사를 통과했다.
- `DONE-VERIFIED`: 카드가 요구한 실기기·실서버·실거래·운영·법률·독립 검토까지 통과했다.
- 단계 완료: 그 단계의 필수 카드가 모두 `DONE-VERIFIED`이고 운영자 출시 서명이 있다.

## 2. 절대 비하향 계약

모든 카드에서 아래 12개를 검사한다.

1. 월 무료 1GB를 없애거나 줄이지 않는다.
2. 확정된 충전·추천 잔액을 임의 만료하지 않는다.
3. 공식 WireGuard를 1단계 기본 경로로 유지한다.
4. 기존 `ffvpn`과 다른 프로필을 자동 삭제·덮어쓰기·활성화하지 않는다.
5. 공개 모바일·PC URL과 서비스 주소 QR을 유지한다.
6. 실제 IP·개인키·공개키·설정 원문·세션 열쇠·방문 기록을 화면·로그·영수증에 저장하지 않는다.
7. 자동·브라우저·실기기·실거래·운영·전문가·가상 사용자 증거를 섞지 않는다.
8. Kakao Connect와 연구 통신 방식은 기본 꺼짐·비공개·판매 제외를 유지한다.
9. Drive B를 연결·읽기·쓰기·복원·삭제하지 않는다.
10. 기존 고객 권리나 공개 자료를 되돌릴 수 없는 방식으로 바꾸지 않는다.
11. 근거 없는 `무로그`, `완전 익명`, `최고 보안`, 국가 성공률, 속도·혼잡 수치를 만들지 않는다.
12. 자동 갱신을 기본값으로 켜지 않는다.

하나라도 깨지면 작업을 완료 처리하지 않고 해당 변경만 되돌릴 수 있게 분리한다.

## 3. 낮은 숙련도 AI용 공통 작업 절차

### 3.1 시작 전

```powershell
git status --short --branch
Get-Content .project-continuity/STATE.md -TotalCount 80
Get-Content .project-continuity/HISTORY.md -TotalCount 60
```

- 기존 변경을 기록하고 초기화하지 않는다.
- 현재 카드와 기존 변경 경로가 겹치면 줄 단위로 보존한다.
- `.project-continuity/LOCK*.json`은 만들지 않는다.
- 비밀값 원문을 터미널에 출력하지 않는다.

### 3.2 구현 순서

1. 카드의 기존 자산과 전용 검사를 읽는다.
2. 실패해야 하는 표본을 먼저 검사해 현재 검사가 실제로 잡는지 확인한다.
3. 데이터 구조·순수 계산을 먼저 구현한다.
4. API 쓰기에는 권한·현재 판번호·중복 처리 방지·감사 사건을 붙인다.
5. 화면은 공통 8상태를 구현하고 빈 값을 성공 숫자로 채우지 않는다.
6. 원본 `20_SRC`를 수정한 뒤 기존 생성 도구로 `30_DEPLOY`를 만든다. 생성 결과만 직접 고치지 않는다.
7. 전용 검사→전체 검사→비밀값 검사→파일 목록 검사→Git 차이 검사 순으로 실행한다.

## 4. 증거 공통 구조

모든 보호·노드·원장·결제·삭제·공개 증거는 아래 필드를 사용한다.

```json
{
  "evidence_id": "비밀값 없는 무작위 또는 사건 ID",
  "subject_scope": "session|device|account|node|release",
  "observed_at": "RFC3339 UTC",
  "expires_at": "RFC3339 UTC 또는 null",
  "source_class": "automatic|browser|android|windows|iphone|transaction|operation|expert|persona",
  "result": "pass|fail|partial|unknown",
  "redaction": ["ip", "key", "account"],
  "version": {
    "app": "판번호",
    "api": "판번호 또는 null",
    "node": "비식별 판번호 또는 null",
    "policy": "판번호 또는 null"
  }
}
```

규칙:

- `observed_at`이 없으면 성공으로 표시하지 않는다.
- `expires_at`을 넘으면 `stale`이다.
- `source_class=persona`는 실제 고객 증거가 아니다.
- 가상 사용자 증거가 아니다라는 구분을 화면·영수증·대시보드에서도 유지한다.
- `source_class=automatic`은 Android·결제·법률 증거를 대신하지 않는다.
- 실제 주소는 일치 여부만 기록하고 원문을 남기지 않는다.

## 6. 상태값과 멈춤 조건

| 상태 | 사용할 때 |
|---|---|
| `READY` | 선행 작업이 끝나 지금 시작 가능 |
| `PLANNED` | 선행 작업이 남음 |

다음 상황이면 즉시 신규 발급·결제·공개 확대를 멈춘다.

- 보호 성공 표기와 실제 경로 불일치

- 무료·충전·추천 권리 손실이나 중복 차감
- 결제와 잔액 불일치
- 오래된 서버 자료가 정상으로 표시됨
- 승인 비용 상한 접근
- 법률·운영 주체 미확정 상태에서 유료 공개 시도

8. 작업 영수증·대시보드·STATE·HISTORY·TEST_EVIDENCE가 같은 상태인가?
