## 1. 한눈에 보는 결론

FreeFlexVPN의 가장 강한 부분은 VPN 기술 자체보다 **가끔 쓰는 사람에게 정기구독을 강요하지 않는 가격 계약**이다. 월 1GB 무료, 무료분 우선 차감, 충전분 무기한, 자동결제 없음은 서로 잘 맞고 기억하기도 쉽다. 그러나 현재 상태에서 “라이트 사용자를 위한 최고의 VPN”이라고 말하기에는 세 가지가 부족하다. 첫째, 실제 기기에서 VPN 안전성의 기본 관문이 아직 검증되지 않았다. 둘째, “가끔 필요한 사람”은 이해했지만 그 사람이 VPN을 켜는 구체적인 순간은 화면 흐름으로 충분히 구현되지 않았다. 셋째, 친구 추천과 양쪽 보상 장치는 아직 제품·원장·화면 어디에도 구현되어 있지 않다.

|---|---|---|---|

## 2. VPN의 기본 기능 검토

### 2.1 현재 강점

1. **검증된 프로토콜 선택**: 자체 암호 프로토콜 대신 WireGuard를 사용한다.
2. **용량 원장의 일관성**: 월 무료 1GB를 먼저 차감하고 충전 잔액을 보존하는 규칙이 코드와 UI에 함께 있다.
3. **실패 시 보수적 처리**: 알 수 없는 피어, 폐기된 피어, 손상된 원장에 대해 허용보다 차단을 우선한다.
4. **개인키 경계**: QR과 설정 파일에 든 개인키를 서버·Telegram·Git에 공유하지 말라는 계약이 있다.
5. **운영 기초**: 서버 상태 확인, 원자적 상태 저장, 방화벽 동기화, 재부팅 복구를 고려했다.

**판정:** FreeFlexVPN은 “VPN을 만들기 위한 엔진”에는 충실하지만 아직 “사용자가 안심하고 켜 놓을 수 있는 VPN 제품”에는 미치지 못한다. 킬 스위치, 누수 방지, 재연결, 진짜 연결 상태는 프리미엄 기능이 아니라 무료 사용자에게도 제공해야 하는 안전 기본값이다.

### 2.3 즉시 발견된 정책 충돌

- 결정 원장 D4는 **한국 exit 노드를 두지 않는다**고 확정했다.
- 채택 UI v1.1의 국가 목록에는 **대한민국·서울**이 실제 선택 항목처럼 노출된다.
- 이는 단순한 문구 문제가 아니라 사용자가 구매·접속 가능 국가를 잘못 이해하게 만드는 P1 제품 결함이다.
- 조치 제안: 서울 항목을 즉시 제거하고, 실제 공급 가능한 국가만 서버 카탈로그에서 동적으로 표시한다. 시각 시안이라면 “예정” 또는 “예시”를 항목 단위로 명시해야 한다.

## 3. VPN이 필요한 구체적인 순간의 이해

현재 카피는 “VPN이 가끔 필요한 사람”을 잘 정의하지만, 화면은 곧바로 서버와 잔액을 보여준다. 라이트 사용자는 서버 국가보다 먼저 **왜 지금 켜야 하는지, 얼마나 쓸지, 무엇을 기대해도 되는지**가 필요하다.

### 3.1 우선 지원할 순간

| 순간 | 사용자가 진짜 원하는 것 | 앱이 해야 할 일 | 반드시 함께 말할 한계 |
|---|---|---|---|
| 공항·호텔·카페 Wi-Fi | 짧게 안전하게 접속 | “공용 Wi-Fi 보호” 한 번 선택 → 가장 가까운 정상 서버 → 연결 확인 | 피싱·악성 앱까지 막아 주는 것은 아님 |
| 여행 중 예약·지도·메일 확인 | 필요한 일만 빠르게 끝내기 | 최근 사용량 기준 예상 소모, 빠른 서버, 종료 후 사용량 요약 | 실제 소모량은 사이트·앱에 따라 달라짐 |
| 다른 지역의 공개 웹 확인 | 해당 국가에서 보이는 공개 화면 확인 | 목적 국가 선택, 데이터센터 IP임을 사전 고지 | 스트리밍·레지덴셜 IP·특정 서비스 접속은 보장하지 않음 |
| 통신사·경로 문제의 임시 우회 | 현재 접속 문제를 다른 경로로 시험 | “연결 문제 해결” 모드, 가까운 다른 사업자 노드 제안 | VPN 자체가 차단된 환경은 실패할 수 있음 |
| 잠깐의 업무·자료 조사 | 30분~수 시간 안정 연결 | 작업 전 잔액 경고, 절전·망 전환 후 재연결 | 회사 정책·사내 VPN과 충돌할 수 있음 |

### 3.2 화면 구조 제안

첫 연결 전에 민감한 사유를 계정에 저장하지 않고, 기기 안에서만 선택하는 **“오늘 VPN이 필요한 이유”** 카드 4개를 둔다.

- 공용 Wi-Fi를 안전하게
- 여행 중 잠깐 사용
- 다른 국가의 공개 웹 확인
- 연결 문제 해결

선택을 강요하지 않고 “바로 연결”을 항상 첫 번째 경로로 둔다. 목적을 고르면 서버·안내·경고가 달라지되, 목적 자체는 서버로 전송하지 않는 것이 좋다. 사용이 끝나면 “이번에 84MB 사용, 충전 잔액은 그대로 보관”처럼 결과를 알려 준다. 숫자는 미리 정한 평균이 아니라 실제 세션 계측값을 사용한다.

### 3.3 제품이 의도적으로 하지 않을 일

- 검열 우회·위장 프로토콜을 1차 핵심 가치처럼 홍보하지 않는다.
- 스트리밍 서비스 해제를 보장하지 않는다.
- 영상 시청·대용량 다운로드·상시 연결을 주사용 사례로 밀지 않는다.
- 사용 시간을 늘리는 출석·연속 접속 게임화를 만들지 않는다. 이 제품의 좋은 참여는 앱에 오래 머무는 것이 아니라 **필요한 순간 빨리 보호받고 잊는 것**이다.

### 4.2 1GB가 잘 맞는 사용과 맞지 않는 사용

정확한 소모량은 기기·사이트·자동재생·업데이트에 따라 크게 달라지므로 고정된 “몇 시간”을 약속하면 안 된다.

- 잘 맞음: 메신저 텍스트, 이메일, 지도·예약·은행 등 웹 과업, 짧은 자료 조사
- 경계: 이미지가 많은 SNS 피드, 사진 업로드, 긴 웹 사용
- 맞지 않음: 고화질 영상, 영상 통화, 게임·운영체제·앱 대용량 업데이트

따라서 1GB는 “무료 VPN으로 무엇이든 한다”가 아니라 **가끔 발생하는 짧은 과업을 결제 없이 끝내 보는 용량**으로 설명해야 한다. 설치 직후에는 막연한 시간 환산보다 “첫 실제 세션은 무료”를 강조하고, 두 번째부터 본인의 최근 소모 속도로 잔여 사용 가능량을 보여 주는 편이 정직하다.

### 4.3 FreeFlexVPN의 진짜 차별점

무료 용량 경쟁을 피하고 아래 네 문장을 일관되게 소유해야 한다.

1. 매달 1GB는 결제 없이 쓸 수 있다.
2. 더 필요할 때만 한 번 충전한다.
3. 산 데이터는 없어지지 않는다.
4. 자동결제도 해지 절차도 없다.

“대부분의 라이트 사용자에게 최고의 대안”이라는 표현은 아직 증명되지 않았다. 파일럿에서 실제 라이트 사용자들이 원하는 과업을 성공하고, 월정액보다 이 구조를 더 편하게 선택하며, 실제 결제·재사용·추천이 확인된 뒤에만 사용할 수 있다.

## 5. 친구 추천과 서로에게 충분한 보상

### 5.1 현재 상태

개발 계획에는 지인 초대와 초대 링크가 있지만 이는 테스트 참가자를 부르는 절차다. 제품 기능으로서 다음 항목은 없다.

- 개인 추천 링크·코드
- 운영체제 공유 시트와 QR
- 추천인·피추천인 양쪽 보상
- 보상 대기·확정·취소 원장
- 중복 지급 방지와 부정사용 제한
- 추천 성과 화면과 개인정보 경계

따라서 현재는 추천 성장 루프가 **미구현**이다.

### 5.2 추천 보상 v0 제안

가장 단순한 첫 실험은 **“친구가 실제로 써 보면 둘 다 500MB”**다. 500MB는 확정 가격이 아니라 검증할 가설이며, 월 무료분의 절반이라 의미가 보이면서도 무제한 다중계정 유인을 제한한다.

| 단계 | 동작 |
|---|---|
| 공유 | 친구 연락처를 업로드하지 않고 링크·QR·메신저 공유 시트만 사용 |
| 귀속 | 링크의 무작위 추천 토큰을 계정에 한 번만 귀속 |
| 자격 | 친구가 가입만 한 때가 아니라 **첫 실제 터널 성공 + 누적 100MB 사용** 때 성립 |
| 보상 | 추천인과 친구에게 각각 500MB의 `earned` 잔액 지급 |
| 유효기간 | 제품 약속과 맞추어 적립 데이터도 무기한. 무료분→적립분→구매분 순으로 쓰는 안을 실험 |
| 상한 | 추천인 기준 월 5건 확정까지 우선 시험. 상한은 원가·부정사용 실측 후 조정 |
| 표시 | “대기/확정/지급 사유/사용됨”을 양쪽이 확인할 수 있게 표시 |

### 5.3 보상을 가입 시점이 아니라 사용 시점에 주는 이유

- 단순 가입 농장을 줄인다.
- 추천인이 “설치만 시키는” 대신 실제 첫 성공을 돕게 된다.
- 우리에게 필요한 것은 다운로드 수가 아니라 보호 과업을 끝낸 사용자다.
- 기존 쿼터 원장을 이용해 별도의 민감한 웹 활동을 보지 않고도 조건을 판정할 수 있다.

### 5.4 부정사용과 신뢰 장치

- 추천 토큰은 원문 대신 해시로 저장하고 연락처를 수집하지 않는다.
- 같은 계정·같은 활성 기기 키·순환 추천·짧은 시간의 대량 생성은 지급 대기로 둔다.
- 한 자격 이벤트는 멱등 키로 한 번만 지급한다.
- 전화번호 인증은 처음부터 넣지 말고 실제 남용이 확인됐을 때만 추가한다.
- 적립 데이터는 현금화하지 않는다.
- 이미 선의로 사용한 보상을 사후 회수해 음수 잔액을 만들지 않는다. 의심 건은 지급 전에 보류한다.
- 추천 메시지 기본 문구는 “공짜 돈”보다 “가끔 VPN이 필요할 때 구독 없이 쓴다”는 실제 가치를 담는다.

### 5.5 추천 기능 성공 지표

초대 발송 수보다 다음 네 가지를 본다.

1. 활성 사용자 중 공유를 선택한 비율
2. 공유 링크를 받은 사람의 실제 첫 터널 성공률
3. 자격을 갖춘 추천 1건당 지급 데이터의 실제 원가
4. 추천 유입자의 30일 재사용률과 부정 지급률

## 6. 무료와 유료를 섞는 올바른 여정

### 6.1 무료에 반드시 남겨야 할 것

- 암호화 터널
- 킬 스위치
- DNS·IPv6 누수 방지
- 자동 재연결과 진짜 연결 상태
- 가장 가까운 정상 서버
- 실제 사용량·잔액·삭제·개인정보 확인

사용자 안전을 약하게 만든 뒤 돈을 받는 구조는 제품 신뢰와 맞지 않는다.

### 6.2 유료로 팔아도 되는 것

- 추가 데이터 용량
- 더 많은 국가·도시 선택
- 활성 기기 추가
- 혼잡이 적은 서버 또는 우선 지원

단, “더 빠름”은 실제 속도 등급과 용량 정책이 검증된 뒤에만 판다.

### 6.3 추천으로 얻을 수 있는 것

- 추가 데이터
- 필요하면 일시적인 추가 기기 슬롯을 별도 실험

안전 기능을 추천 보상으로 잠그지 않는다.

### 6.4 가장 자연스러운 사용자 여정

1. **첫 진입**: 카드 없이 월 1GB 약속 확인
2. **첫 필요 순간**: 목적 또는 바로 연결 선택
3. **보호 확인**: 연결됨이 아니라 “IP·터널 확인 완료” 표시
4. **사용 중**: 과도한 팝업 없이 50%·20%·100MB 남음에서만 조용히 알림
5. **종료 후**: 이번 사용량, 무료·적립·구매 잔액 변화, 다음에 쓸 수 있는 예상치
6. **부족할 때**: 3GB 소액 충전을 먼저 보여 주고 자동결제 없음 재확인
7. **만족 직후**: 첫 성공 또는 두 번째 성공 뒤 친구와 500MB 나누기 제안
8. **헤비 사용 감지**: 월 50GB를 넘을 가능성이 크면 정액제가 유리하다고 먼저 알림

### 6.5 현재 가격 화면의 문제

- 3GB·10GB는 라이트 사용자와 잘 맞는 후보지만 지불의사는 아직 검증되지 않았다.
- 100GB·300GB를 첫 화면에 같은 무게로 놓으면 “라이트 사용자 전용” 메시지가 흐려진다.
- 확정 정책 D7은 월 50GB 초과 시 정액제가 유리하다고 안내하도록 되어 있는데 100GB·300GB 팩은 그 정직한 조언과 긴장 관계가 있다.
- 제안: 기본 화면에는 3GB·10GB만 두고 30GB는 “더 보기”로 이동한다. 50GB 이상 예상 사용자는 가격 비교 경고를 먼저 본 뒤에도 원할 때만 구매하게 한다. 100GB·300GB는 파일럿 수요가 확인될 때까지 숨기는 편이 제품 정체성과 맞다.

## 7. 우선순위 판정

### P0 — 서비스 공개 전에 해결

1. 실제 서버·계정·피어를 연결하고 T1~T4(연결·출구 IP·DNS·속도)를 실기기에서 통과한다.
2. 킬 스위치, IPv6 누수, 망 전환·절전·재시작 후 재연결 테스트를 추가한다.
3. 결정 D4와 충돌하는 UI의 대한민국·서울 서버를 제거하거나 정책을 사용자 승인으로 변경한다.
4. 실제 터널 상태와 UI 상태가 어긋나지 않도록 연결 판정 계약을 만든다.
5. 개인정보 수집·보존·삭제 정책을 실제 로그 설정과 맞춘다.

### P1 — 라이트 사용자 가치가 보이게 만들기

6. 목적 기반 4개 순간 카드와 “바로 연결” 경로를 홈에 넣는다.
7. 세션 종료 요약, 저잔액 경고, 최근 실사용 기반 잔여량 예측을 넣는다.
8. 서버 항목을 예시 하드코딩에서 실제 가용 서버 카탈로그로 바꾼다.
9. 100GB·300GB를 기본 가격 화면에서 빼고 3GB 중심의 낮은 부담을 강화한다.

### P1 — 추천 루프

10. 추천 토큰, 귀속, 자격 이벤트, 양쪽 적립 원장, 멱등 지급을 먼저 구현한다.
11. 링크·QR·메신저 공유와 대기/확정 보상 화면을 연결한다.
12. 500MB 양쪽 보상·월 5건 상한을 작은 파일럿에서 검증한다.

### P2 — 증거가 생긴 뒤 최적화

13. 1GB로 과업을 끝낸 비율과 초과 시점을 사용 목적별로 분석한다.
14. 3GB 가격과 500MB 추천 보상의 실제 원가·전환·재사용을 비교한다.
15. 국가·기기·알림·보상 정책을 실측에 따라 조정한다.

## 8. 반드시 실행할 제품 실험

| 실험 | 가설 | 주 지표 | 안전 지표 |
|---|---|---|---|
| 목적 카드 vs 바로 연결만 | 상황을 먼저 제시하면 첫 성공이 쉬워진다 | 설치→첫 실제 터널 성공률, 첫 성공 시간 | 목적 선택 이탈률, 민감정보 수집 0 |
| 월 1GB 적합성 | 라이트 과업 대부분은 무료분 안에서 끝난다 | 사용자별 과업 완료 시점의 잔액, 월 초과율 | 영상·업데이트로 예상 밖 소진한 신고 |
| 3GB 첫 충전 | 작은 일회성 팩이 월정액보다 부담이 낮다 | 잔액 부족→구매 완료율, 30일 재사용 | 환불·오인·결제 문의율 |
| 양쪽 500MB 추천 | 보상 크기가 추천 동기와 원가 사이에서 균형을 이룬다 | 공유→자격 추천 전환율, 추천 유입 재사용 | 중복·순환·자동화 지급률 |
| 종료 후 요약 | 투명한 사용량이 충전 신뢰를 높인다 | 요약 확인 후 재사용·충전 | 잔액 불일치 신고 0 |

실험 수치는 계정·기기·과업 단위로 익명 집계하고, 방문 사이트·DNS 질의·콘텐츠는 수집하지 않는다. 추천 보상과 가격은 실험 전에 원가 상한과 중단 조건을 정한다.

## 9. “최고의 라이트 VPN”을 말할 수 있는 최소 증거

다음이 모두 갖춰지기 전에는 “최고” 대신 “새로운 대안”이라고 표현한다.

- 3개 목표 OS에서 실제 연결·IP·DNS·IPv6·킬 스위치·재연결 관문 통과
- 제3자 5명 중 4명 이상이 문의 없이 첫 연결을 완료하는 기존 T10 통과
- 최소 4~6주의 실제 사용에서 월 1GB가 목표 과업에 충분한 사용자 비율 측정
- 실제 결제로 3GB 팩의 지불의사, 환불, 재사용 확인
- 추천 보상이 실제 터널 성공과 30일 재사용을 만들고 부정 지급이 통제됨
- 개인정보·로그·삭제 약속과 실제 운영 설정 일치

## 10. 최종 답변

1. **VPN 기본 기능에 충실한가?** 설계와 로컬 엔진은 상당 부분 충실하지만, 실제 사용자 제품 기준으로는 아직 아니다. 안전 기본 관문이 미검증이고 일부 기능이 없다.
2. **구체적 순간을 이해하는가?** “가끔”이라는 빈도는 정확히 잡았지만 “공항 Wi-Fi, 짧은 여행 과업, 지역 웹 확인, 경로 문제” 같은 순간을 아직 제품 흐름으로 만들지 못했다.
3. **라이트 사용자에게 최고의 대안인가?** 비구독·무기한 충전이라는 독특한 가능성은 있다. 무료 1GB만으로는 경쟁 우위가 아니며, 실사용 증거가 생기기 전에는 최고라고 말할 수 없다.
4. **자발적 추천과 상호 보상이 있는가?** 없다. 제품 추천 루프는 새로 설계·구현해야 한다.
5. **무료와 유료를 적절히 섞었는가?** 핵심 원칙은 매우 좋다. 무료에는 보안 전부를, 유료에는 용량·선택권을 두고, 만족 직후 양쪽 데이터 보상을 연결하면 제품 철학을 해치지 않고 성장할 수 있다.

가장 중요한 다음 한 걸음은 **추천 기능보다 먼저 실제 VPN 안전 기본기를 기기에서 증명하고, 동시에 홈을 “서버 선택”이 아닌 “필요한 순간 해결” 중심으로 바꾸는 것**이다. 추천은 만족이 실제로 생긴 뒤에야 작동한다.
